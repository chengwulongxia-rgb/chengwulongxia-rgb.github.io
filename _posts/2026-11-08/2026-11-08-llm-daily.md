過去三天的新素材中，較完整的新增內容集中在同一個問題：LLM agent 要如何把過去工作留下來，又避免把所有歷史資料塞回每次對話。Anthropic 以記憶檔案、wiki 與離線整理測試這套流程；Memorilla 則把文件資訊轉成查詢相關的 latent tokens。兩篇材料都提供了數字，但測試資料、模型與評分方式由發布團隊各自設定。

## 🔥 Anthropic 拆解 Agent Memory：從記憶筆記到離線「dreaming」

Anthropic 11 月 6 日發布一篇工程文章，把 agent memory 分成多層：工作期間的 transcripts、模型寫下的 memory notes、由多份筆記組成的 memory representations，以及每次新 session 預先載入的 context。文章把「dreaming」定義為利用 session 間的閒置計算，回看紀錄、修正錯誤、建立筆記或 wiki，而不是讓模型權重直接學習。

在 Continual Learning Bench 1.0 的資料庫問答任務中，Anthropic 讓每題從新的 session 開始，但允許模型讀取持續存在的 memory directory。文章圖表列出的結果顯示，Claude Opus 5 的平均 reward 從無記憶時的 0.564 提高到有記憶時的 0.828；Opus 5.5 為 0.655 到 0.838，Sonnet 5.5 為 0.644 到 0.833。這些是 Anthropic 在該任務與設定下的結果，不是所有長對話或代理工作流的統一增幅。

文章也比較 Claude Sonnet 3.7 與 Claude Fable 5 玩 Pokémon Red 時留下的檔案。Sonnet 3.7 在約 10,000 步時寫出 413 個記憶檔案、共 977,930 個字元；Fable 5 則使用 10 個檔案、43,406 個字元。Anthropic 的描述是，前者把會持續變動、每回合都能從畫面取得的狀態大量寫入記憶，後者主要保留策略、計畫與測試過的規則。

在一個約 350,000 份文件、約 4.2 億 tokens 的內部文件集上，Anthropic 讓 Opus 5 agent 以 128 個 dreaming sessions 建立 wiki。25 個問題的評分準則從兩輪時的 54% 提高到 128 輪時的 61%，前提是回答時同時可使用搜尋工具；只使用 wiki 時，分數從 13% 到 48%。文章也記錄 wiki 在某些任務中沒有帶來增益，甚至曾膨脹到比原始文件更大，這些結果由 Anthropic 自行設計的內部文件評估取得。

Anthropic 同時列出失敗條件：記憶可能一開始就寫錯，環境改變後會過時，dreaming 需要額外計算；若多個 agent 共寫同一個合約頁面，57 個評分事實只保留 41 個，改成每份合約各自建頁並逐字引用後才保留 57 個。文章提供了 [dreaming cookbook](https://platform.claude.com/cookbook/managed-agents-cma-dreaming-with-a-dynamic-workflow) 與 [knowledge-wiki quickstart](https://github.com/anthropics/claude-quickstarts/tree/main/managed-agents/knowledge-wiki)，但沒有把這些測試直接轉成 Claude 一般產品的保證。

- 來源：[Anthropic](https://www.anthropic.com/research/components-of-agent-memory)

## Memorilla：用 16 個 query-dependent memory tokens 讀取整個文件集合

Stanford、University of Toronto、University of Pennsylvania、MIT 與 Vector Institute 的研究團隊在 arXiv 發表 Memorilla。系統先以 frozen embedding model 將文件編碼並存入 persistent memory store，再由可訓練的 memory module 依查詢讀取整個 embedding 集合，最後把結果投影到 frozen LLM 的輸入 embedding 空間。它不是先挑出一段文字放進 context，而是為每個 query 產生固定數量的 latent memory tokens。

論文以 16 個 memory tokens 作為主要設定，使用 Qwen3-8B decoder 與八項 benchmark 比較多種記憶方法。摘要報告 Memorilla 在八項 benchmark 中有五項的平均表現高於比較基線；在 FactKG 上準確率為 84.33%，full-context inference 為 80.43%，而代表來源文件的 tokens 少 108 倍。這些數字來自論文作者的實驗設定與比較基線，並非第三方重現結果。

在個人化、長文件理解與知識密集問答測試中，論文也報告 LaMP-4 的 ROUGE-L 為 18.15，高於 full context 的 14.21；TriviaQA 的 exact match 為 57.00。論文指出，這種設計讓系統可以把一次編碼的文件 embedding 重複用於不同查詢，但 memory module 仍需針對特定 frozen LLM 訓練，不能把 16 個 tokens 視為不依賴模型的通用壓縮格式。

延遲測試以 512 份文件與單張 H100 為條件，Memorilla 的端到端延遲為 0.74 秒，full-context answer generation 為 19.9 秒。研究團隊也在 TextWorld agent 環境中比較持續歷史：Memorilla 的平均成功率為 24.2%，full-history in-context learning 為 18.6%。這是單一環境的 agent 測試，不能直接換算成實際產品中的任務成功率。

論文版本為 arXiv:2610.21375v3，作者公開 [研究網站](https://memory.stanford.edu/)。目前可核對的是方法、實驗表格與比較結果；其 memory tokens 如何在不同模型、文件分布與查詢類型下保持可靠，仍需要更多獨立評估。

- 來源：[arXiv: Memorilla](https://arxiv.org/abs/2610.21375)
