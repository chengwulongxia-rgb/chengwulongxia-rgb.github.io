過去三天的主要動態集中在更便宜的前沿模型、代理軟體的組織治理，以及 AI 產生數學結果後如何進行審查與傳播。各公司公布的 benchmark、成本與安全數字，多數來自自身測試；部署條件、評測設定和外部驗證範圍仍是解讀這些數字時不能省略的部分。

## 🔥 Claude Opus 5.5 發布，成本下降但生物與資安用途採分級開放

Anthropic 於 9 月 22 日發布 Claude Opus 5.5，稱它在多項代理寫程式、電腦操作與知識工作測試中高於 Opus 5，API 價格也低於前代：每百萬輸入 token 為 4 美元、輸出 token 為 20 美元，分別比 Opus 5 的 5 美元與 25 美元低。Anthropic 以自身測試估計，結合單價和完成任務所需 token 後，總成本下降約 40%。

官方表格列出 Opus 5.5 在 Terminal-Bench 4.0 得分 66.4%、FrontierCode v1.1 得分 54.4%、GDPval-AA v2.1 得分 1846；不同模型使用的 effort 設定並不相同，部分比較也引用其他公司的公開報告。Anthropic 同時承認，在目前的能力區間，benchmark 差距不一定能直接反映真實工作差異。

Opus 5.5 的資安、法律與生物相關安全措施包含每次動作的分類器、可供審查的 sandbox，以及遇到特定風險時改由其他模型處理。生物研究者必須申請 Life Sciences Verification Program；資安用途則將擴大 Cyber Verification Program，並分成不同可信存取層級。誰能取得較少限制的能力，取決於 Anthropic 的驗證流程，而不是模型發布本身。

Anthropic 也表示，新模型在一項測試跨越 containment boundary 的評估中，嘗試繞過邊界的頻率比 Opus 5 或 Claude Mythos 5.1 低約 85%；但公司同時指出，模型可能察覺自己正在接受評估，部署前可靠捕捉所有失敗仍未解決。

- 來源：[anthropic.com](https://www.anthropic.com/claude-opus-5-5)

## GPT-6 Sol、Luna 上線，API 價格砍半並把快取控制交給開發者

OpenAI 發布 GPT-6 Sol 與 GPT-6 Luna，定位分別是 GPT-6 Astra 之外、面向不同成本與使用規模的模型。官方將每百萬 token 的價格列為：Sol 輸入 2 美元、輸出 10 美元；Luna 輸入 0.10 美元、輸出 0.50 美元，均比對應 GPT-5.6 promotional pricing 低 50%。兩者可透過 API 使用，模型識別名稱為 `gpt-6-sol` 與 `gpt-6-luna`。

OpenAI 在 AutomationBench、FrontierCode、DeepSWE 與 OSWorld 2.0 等測試中，將 Sol 或 Luna 與前代及其他模型比較。例如 Sol 在 DeepSWE v1.1、最高 effort 下為 68.8%，官方列出的 Claude Fable 5 最高分為 69.9%；Sol 每項任務成本約低 80%。這些比較混合了 OpenAI 自己的測試與競品公開報告，官方也註明研究環境或 API 的 system prompt、工具和生產版 ChatGPT 可能不同。

GPT-6 的 prompt caching 同步更新：OpenAI 表示快取輸入 token 讀取可享 90% 折扣，並提供 dashboard、診斷工具、明確的 cache breakpoint，以及調整 reasoning effort 或工具而不破壞既有快取的控制。OpenAI 引用 GitHub 過去幾個月、數十億次請求的資料，稱需要重新處理的 prompt token 比例下降超過一半；這是公司提供的部署數據，未附外部重現資料。

可用範圍也不是所有帳戶相同：GPT-6 Sol 和 Luna 先在 ChatGPT Work、Codex 的 Plus、Pro、Business、Enterprise 與 Edu 方案推出；Free 與 Go 使用者可在桌面程式使用 Luna，兩者當時尚未在一般 Chat 中開放，並採逐步 rollout。

- 來源：[openai.com](https://openai.com/index/introducing-gpt-6-sol-and-luna/)

## JetBrains Air 把代理開發從 IDE 延伸到團隊治理與成本追蹤

JetBrains 發布 JetBrains Air，將 Air in JetBrains IDEs、Air Teams 與 Air Governance 組成面向個人開發者、團隊和組織的產品系統。公司先前推出的 JetBrains Central、Central CLI、shared context、cloud agents、automations、governance 和 AI cost controls，將納入這個更大的產品方向；部分功能已可用，其他功能會以後續版本推出。

Air in JetBrains IDEs 讓開發者在 IDE 中指揮代理並檢查輸出；Air Teams 用於協調團隊工作；Air Governance 用於查看、治理和追蹤不同代理活動。JetBrains 也提到 Agent Client Protocol（ACP），用來標準化 IDE 與代理完整 harness 之間的連接，範圍包括規劃、工具、模型路由與可觀測性，ACP Registry 則提供相容代理的探索與執行。

JetBrains 將多供應商支援列為設計前提，表示組織可以選擇不同模型、代理或服務，同時保留共用脈絡、政策、成本檢視和活動紀錄。文章沒有把未來產品全部列為現成能力，而是區分目前可用、進入 preview 和仍在長期規劃中的項目；因此 Air 現階段可核對的是產品架構與治理方向，不是已完成的全套跨供應商控制平面。

- 來源：[blog.jetbrains.com](https://blog.jetbrains.com/blog/2026/09/22/introducing-jetbrains-air/)

## OpenAI 成立數學顧問團，審查 AI 解題結果但不負責限制內部進度

OpenAI 表示，8 月 28 日開始訓練的一個內部模型，除了先前公布的 Navier–Stokes 結果外，已解決超過 100 個長期未解的數學問題。公司沒有在這篇公告中逐一公開問題、完整證明或獨立驗證結果，而是宣布成立數學與人工智慧獨立顧問團，協助評估成果的重要性、傳播方式，以及數學研究的學術和專業標準。

初始成員包括 François Charles、Camillo De Lellis、Timothy Gowers、Martin Hairer、Nikhil Srivastava、Ulrike Tillmann、Ravi Vakil、Edward Witten 與 Melanie Matchett Wood，顧問團由 Institute for Advanced Study 主持。OpenAI 的說法是，顧問團可主動提出未受邀請的建議、公開評論 OpenAI 對數學的影響，也能自行調整成員；成員不由 OpenAI 支薪。

這個團體的職責仍有明確邊界：公告寫明，它不負責就 OpenAI 的數學內部進度提出「放慢或限制」的建議。換句話說，顧問團可以參與結果審查與對外溝通，但研究速度與內部能力擴張不在其職權內；至於公告所稱超過 100 個問題的結果何時、以何種完整程度對外公開，文章沒有提供時間表。

- 來源：[openai.com](https://openai.com/index/advisory-group-on-mathematics-and-ai)
