Jono 以一個月、十多個專案的密集使用經驗，說明為何他把 DeepSeek 4.1 Flash 當成前沿模型使用；文章同時談到第三方 benchmark、長工作階段的成本、KV cache、自架模型的經濟帳，以及中國模型與前沿實驗室不同的商業條件。以下數字與判斷均依原作者敘述整理，未經本文獨立驗證。

## 原文摘要

### 一個月實測：作者主觀上難以分辨 DeepSeek 與 Opus

Jono 表示，自己已密集使用 DeepSeek 4.1 Flash 約一個月，橫跨十多個專案。就他的主觀使用感受而言，這個模型能力很強，價格又比所謂的「前沿」模型低上數個數量級。當工作階段進行到一半，如果不看模型名稱，他坦言自己無法只從對話、完成的工作或速度，判斷當下使用的是 DeepSeek 還是 Opus。

因此，他不在意 DeepSeek 並未推出名為 4.1「Pro」的版本，而是直接把 4.1 Flash 當成前沿模型使用。這項判斷首先來自他的個人經驗，不是受控測試。原文另外連到 OneShotLM 的模型頁，作為「它的行為像前沿模型」的外部參考，也提供 Artificial Analysis 上 Claude Opus 5.5 與 DeepSeek V4.1 Flash 的較完整 benchmark 比較。不過，作者沒有在文中逐項拆解測試方法或分數；這些 benchmark 是他引用的佐證，不能與他的親身使用感混為同一種證據。

基於上述經驗，Jono 追問：為何前沿實驗室沒有對此感到更大的壓力？他的判斷是，中國模型可能只落後 Anthropic、OpenAI 一兩個月，但這些經過蒸餾的中國模型已能處理相同類型的工作負載，因此可能奪走大量需求。這是作者對競爭態勢的推論，而非文中以市場數據證成的結論。

他也簡短碰觸訓練資料爭議：一方面連結 TechCrunch 對 Anthropic 指控中國 AI 實驗室挖掘 Claude 輸出的報導，另一方面又反諷 Anthropic 的訓練材料同樣來自其他人的內容。但他刻意不深入討論資料究竟屬於誰，理由是多數開發者做選擇時，優先考慮的往往不是資料權利爭論，而是在預算內能買到多少實際能力。

### 「夠好」之後，工作方式比榜首位置更重要

作者認為，現今模型已足以承擔高品質、無人看守的任務，因此一味追逐最新、最強模型沒有太大意義。新模型展示的新能力當然有趣，但日常交付給模型的工作，往往遠低於它們的能力上限；他用「請數學博士整理桌面檔案」來形容這種落差。

真正改變他開發方式的是低成本。透過每月 10 美元的 OpenCode Go 訂閱，他形容 DeepSeek 幾乎可以不限量使用。成本壓低後，他不再需要為啟動瑣碎任務感到浪費，也能放心安排探索性的 UI monkey testing，甚至把整理桌面檔案之類的工作交給模型。原文舉例，同一件任務若用 DeepSeek，成本可以是 0.003 美元，而不是 1 美元。作者還表示，自己的單次工作階段預估費用很少超過 1 美元；即使他會刻意保持 session 緊湊，有些 session 仍會持續大半天。

這些成本數字是作者依自身帳戶、訂閱與工作方式提出的經驗值，原文沒有提供帳單明細、token 用量、計價拆分或可重現測試，因此適合理解為個案，而不是所有使用者都能直接套用的普遍成本。

Jono 不只把 4.1 Flash 用於低風險雜務，也拿它處理複雜規劃與研究。遇到少數關鍵任務，例如他連結的 RSilo 專案，他有時會請 Opus 5.5 做最後一輪 code review。依他的描述，Opus 會找出少量邊界案例，再由 DeepSeek 實際執行修正。這不是讓 Opus 全程接管，也不是用 Opus 系統性評測 DeepSeek，而是把較昂貴模型放在最終覆核的位置。

他補充，即使臨時改用 Opus 或 GLM，目的也不一定是取得更高能力或品質，而是讓另一個模型以不同視角重新檢查同一個問題。換句話說，在這套流程裡，多模型切換的價值比較接近第二雙眼睛，而不是固定的能力階級。

### 「437 倍」KV cache 主張與環境效益推論

原文把長時間 coding session 的低價，進一步歸因於 KV cache。作者聲稱，DeepSeek 相較自家 V1 模型，把 KV cache 大約縮小了 437 倍。由於長工作階段需要把 cache 保留在 GPU 記憶體中，而這被他視為推論成本的重要來源之一，因此他認為這項縮減，是自己能讓全天 session 維持在 1 美元以下的關鍵原因。

這裡需要分清楚兩層內容：第一層是作者提出的「約 437 倍」技術主張；第二層是他將該主張連到個人帳單的因果解釋。原文沒有在正文交代 437 倍的計算基準、cache 定義、比較條件或實測方法，也沒有展示從記憶體節省換算到終端價格的完整成本模型，因此兩者都應保留為作者說法，而不是已由文章本身驗證的工程結論。

接著，作者推測這種效率提升也應對環境更有利。他說，使用 Claude 幾乎讓他感到浪費，不只因為金錢，也因為他推想 DeepSeek 較小的 cache 應會消耗較少的水與電。原文並未提供能源、用水、資料中心位置、硬體利用率或全生命週期比較，所以這是由 cache 效率延伸出的環境推論，不是環境影響評估。作者另外連到一篇談「cache magic」的文章，並稱同一類技術也讓 Opus 5.5 悄悄獲得效率提升；這同樣是原文引用與判斷，本文未另行核實。

### 不是省小錢，而是長期可持續性與取得門檻

Jono 強調，自己並非沒有前沿模型可用。他擁有相關訂閱，工作也提供 Claude、Cursor 等工具，因此選擇 DeepSeek 不是因為必須錙銖必較。他關注的是長期規劃、服務可持續性，以及讓更多人能取得高水準模型能力。從這個角度看，他把 4.1 Flash 視為足以改變市場的產品。

在他的描述裡，科技產業常把高價格等同於高價值：FAANG 願意用最高預算購買最高智能，即使伴隨倫理、成本、環境或總體經濟問題也照樣競逐。作者將這種行為歸入弱肉強食式的資本主義，並舉出兩種現象：有人為了取得更多 Claude 額度，設計複雜系統在十多個 Claude Max 訂閱間做負載平衡；也有人在不能繼續取得更多額度時公開抱怨。這些連結被他用來支持「產業偏好堆高支出」的觀察，但不是整個產業採購行為的統計調查。

### 自架是否划算：省錢不成立，隱私仍可能成立

談到 self-hosting，Jono 的判斷相當直接：以 4.1 Flash 的服務價格來看，若目標只是省錢，自架並不值得，因為硬體與營運投入不可能回本。這是作者的經濟判斷；原文沒有列出 GPU 採購、折舊、電力、維運、利用率與 API 用量等試算條件，因此不能直接推廣到所有地區、規模或工作負載。

但若自架的動機是隱私，他的結論不同。他預期這些 cache 最佳化終究會進入本地部署，使相同的效率技巧能在使用者自己的硬體上運作。他並稱 4.1 Flash 現在「技術上」已可自架，只是「實務上」仍不現實；至於何時會真正普及，他只以「任何一天都可能到來」表達樂觀期待，沒有提供確切時程。

### PS：把中國模型比作仿製藥

文章發布後因 Hacker News 討論而獲得關注，作者在 PS 補充自己的核心意思：中國公司採用不同的競爭規則，之後也會有更多模型跟進；相較之下，前沿實驗室採取另一套商業模式，必須設法回收訓練新 LLM 的高昂成本。

他以大型藥廠與仿製藥廠作比喻：前者負擔研發成本，後者能跳過部分 R&D，再以低得多的價格提供接近的產品。作者承認這些模型並非一比一複製，但仍認為兩者已接近到足以作「蘋果比蘋果」的比較，而價差可達 90%。這個比喻是在說明不同研發與回收成本結構，不等於他已證明模型能力完全相同，也不等於對資料來源爭議作出法律或倫理判決；「90% 降價」同樣是作者在 PS 中的概括性主張。
