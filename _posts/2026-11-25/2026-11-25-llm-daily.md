近三天的新素材，一部分把 LLM 的用途延伸到蛋白質結構與序列設計，另一部分則回頭整理 coding agent 在一年內的能力變化；研究端也在檢驗代理取得證據的方式是否真的改善決策。這些內容分別來自企業公告、個人技術回顧與受控實驗，適用範圍並不相同。

---

## 🔥 OpenAI 展示 GPT-6 以推理與程式碼進行蛋白質設計

OpenAI 發布文章表示，GPT-6 模型能使用推理與程式碼設計蛋白質結構與序列，並將這項能力稱為模型本身具備的 protein-design capability。公告描述的流程包含提出設計、以程式碼或工具處理候選方案，以及對結構與序列進行檢查；這些是 OpenAI 對模型能力與示範流程的說明。

文章標題與摘要將焦點放在模型直接處理蛋白質設計任務，但公告本身不是經過獨立機構驗證的生物實驗結果。能產生候選結構或序列，不等於候選物已在實驗室中合成、具備預期功能或符合安全要求；實際用途仍需要結構評估、實驗驗證與領域專家審查。這項展示也不代表 GPT-6 可在所有蛋白質設計問題上穩定工作。

## LLM 與 coding agent 的一年變化被整理為三個能力轉折點

Simon Willison 11 月 24 日發表文章，將過去十二個月的 LLM 與 coding agent 能力變化整理成三個轉折點。他以 2025 年 11 月 Claude Opus 4.5 的發布作為第一個時間點，記錄自己使用 Claude Code 時，從需要頻繁修正到多數日常程式問題可直接得到正確結果的經驗；他也把同一時期的 GPT-5.1 系列與 Codex 列入相近的變化。

文章指出，Claude Code 在 Claude 3.7 Sonnet 時期已經推出，但作者直到 Opus 4.5 才把它用於較多日常工作。這是作者的使用經驗與回顧，不是跨使用者的生產力研究，也沒有提供統一任務集、基準測試或失敗率統計。

Willison 另以 2026 年中發布的 Claude Fable 5 回顧模型在資安任務上的能力變化，並把它與先前只能在受限條件下展示的模型區分。文章的「三個轉折點」是作者對一年內事件的整理框架，不是模型供應商共同採用的正式分類。

## 研究比較暴力影片審查代理如何傳遞證據

一篇於 11 月 19 日提交 arXiv 的研究，在 XD-Violence 測試集的 799 段影片上，比較相同感知代理與推理模型在不同資訊介面下的暴力影片審查結果。研究固定影片描述、物件偵測、聲音標記、語音辨識與語音標記等感知元件，再比較代理訊息、可用工具探索的 typed evidence graph、一次讀取的純文字，以及直接接收原始影片的 audio-visual model。

研究報告指出，在測試集上，直接處理影音的模型與純文字介面的 F1 分數分別為 0.968 與 0.967。研究的開發集結果則顯示，把 graph summary 加入純文字後，F1 從 0.946 降至 0.926；把相同資訊改為多輪工具探索後降至 0.896。作者觀察到，graph agent 的錯誤通常不是完全沒有取得相關資訊，而是停止在尚未開啟關鍵片段的位置，或把脫離上下文的物件偵測當成決策依據。

聲音資訊在該實驗中增加了純文字介面的表現：含聲音事件的版本比不含聲音事件的版本高 0.012 F1。研究也檢查引用證據與決策的關聯，隱藏被引用的觀察會改變 49% 的純文字決策，而隨機隱藏只改變 0.6%。結果來自 XD-Violence 資料集與研究者固定的感知元件，不等於所有內容審查工作流或真實部署的準確率。

- 來源：[arXiv](https://arxiv.org/abs/2611.26776)
