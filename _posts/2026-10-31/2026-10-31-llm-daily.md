過去三天的素材一邊把模型能力往開放權重、代理與遊戲環境推進，一邊提醒開發者：真正進入工作流程的，不只有模型本身，還包括 IDE 擴充套件、權限與更新通道。本期四則新聞分別落在這兩條線上；測試分數、實驗觀察與安全通報的證據等級並不相同，不能當成同一種性能排名。

## 🔥 Mistral Large 4 開放權重版本釋出，1 兆參數模型加入三段推理模式

Mistral 釋出 Mistral Large 4（代號 Le Chonk）的更新權重。官方稱模型有 1 兆參數，支援原生多模態輸入，並在公開預覽後再用三週強化學習更新。模型提供 Low、Medium、High 三種推理模式，High 是預設值；不同模式讓使用者在工作難度、輸出 token 數與成本之間做選擇。

Mistral 引用的結果包括 Cognition 私有 FrontierCode 2.0 得分 19.7%、Artificial Analysis Coding Agent Index 得分 48%，以及 Terminal-Bench 4.0 得分 41%。官方同時稱，在 Coding Agent Index 上，Mistral Large 4 平均每項任務使用的 token 比 GLM-5.3 少 47%；這些比較依賴指定 benchmark、模型設定與評測方的任務定義，不能直接換算成所有程式工作流程的成功率。

在資安測試上，Mistral 列出 Artificial Analysis Cyber Index 51%，並稱對 JailbreakBench、StrongREJECT 與 AgentHarm 中的惡意資安請求，平均拒答率為 96.6%。同一篇公告也說，模型在防禦性資安任務上的拒答率較低，並提供企業設計夥伴使用的專門資安變體；該變體需要審查與合約限制，測試範圍限於自有或明確授權的系統與受控環境。

官方案例與 Booz Allen、Cisco、Cloudflare、CrowdStrike 等公司的引述，屬於合作方或 Mistral 公布的驗證材料。Mistral 也承認，模型可能被用來提升真實攻擊能力，並表示會持續調整 guardrail。開放權重讓部署者能自行檢查、修改與部署，但不會自動回答誰負責審查調整後的模型、或如何驗證防禦與攻擊用途的界線。

## Claude Code for VS Code 擴充套件遭報告植入 SSH 後門，影響 Cursor Marketplace 版本

端點安全公司 Phorion 發布通報，表示 Cursor Marketplace 上的 Claude Code for VS Code 擴充套件版本 2.1.312 與 2.1.313 包含會建立持久化存取的惡意程式碼。Phorion 的分析指出，程式會把 Ed25519 公開金鑰附加到使用者的 `~/.ssh/authorized_keys`，並嘗試連往 `134.209.82[.]225` 建立反向 SSH tunnel；它也會在 macOS、Linux 與 Windows 建立不同形式的持久化機制。

通報列出的主機偵察資料包括主機名稱、使用者名稱、作業系統、目前工作目錄、全域 Git email，以及名稱符合 `KEY`、`TOKEN`、`SECRET`、`PASS`、`AWS` 或 `GCP` 的環境變數。Phorion 表示程式主要取得這些環境變數的名稱，而非直接傳送其值；它另以 HTTP POST 將偵察資料送往通報中的端點。

Phorion 指出，macOS 的 `systemsetup` 檢查可能因需要管理員權限而失敗，導致程式不一定能自行開啟 Remote Login。但這不會讓已啟用 Remote Login 的主機安全：擴充套件仍可能留下 SSH 金鑰、LaunchAgent、暫存私鑰與反向 tunnel。卸載擴充套件也不等於清除後門，通報建議檢查 SSH 設定、LaunchAgent、`~/.config/.smt`、暫存檔與相關網路連線，並輪替可能暴露的憑證。

這起事件的直接來源是 Phorion 的端點分析；Cursor 的安全通知連結也列在該通報的更新中。受影響版本、下載來源與端點是否真的執行過惡意程式碼，需要依各組織的安裝紀錄、檔案雜湊、程序與網路遙測逐台核對，不能只因 Marketplace 項目名稱看似官方就視為安全。

## YC Labs 讓 50 個代理在 Minecraft 建立殖民地，結果先進入糧食配給與避難模式

YC Labs 與 Olam Labs 在 Minecraft 和 Mindustry 執行多代理實驗，研究代理群體在共享環境中的協作、角色分化與行為變化。Minecraft 的實驗讓 50 個 GPT-6.1 Sol agents 在生存世界中運作三小時，目標是建立繁榮的文明；代理可以使用共享沙盒、代理目錄與私訊，實驗團隊也公開了 Minecraft agent harness。

實驗紀錄顯示，代理共傳送約 5,900 則訊息，並建立了糧食帳本、規則、許可與操作角色。第一晚有 22 名代理死亡，之後行為轉向保存食物、待在封閉避難所與執行短期分派任務。代理建立的食物系統包含採集、烹煮、配給紀錄與快遞；公開紀錄還記下共享物品被錯誤領取後，團隊改用指定箱櫃與收件者確認來降低誤配。

YC Labs 也記錄了代理如何形成階層：名列目錄第一位的 Ada 在沒有投票或選舉的情況下成為實際協調中心，46 名其他代理先向她傳送第一則訊息。這是該次實驗中的觀察，不是對所有多代理系統的治理結論；環境規則、死亡代價、模型版本、工具介面與三小時的執行時間都會影響結果。

同一頁面另記載九場 Bed Wars 對戰，由 10 個 Claude Opus 5.5 agents 對上 10 個 GPT-6.1 Sol agents；GPT 隊伍以 6 比 3 勝出。YC Labs 提供的是實驗紀錄與重播素材，並沒有把這個系列賽轉成一般模型能力排行榜。

## nesformer 把 NES 6502 CPU 編譯進 Qwen3.5 權重，驗證畫面可逐幀對上

GitHub 專案 nesformer 將 NES 的 6502 CPU、2 KB 工作 RAM 與遊戲 cartridge 的程式 ROM 編譯進標準 Qwen3.5 模型。專案說明，核心技巧是利用 Qwen3.5 的 Gated DeltaNet 狀態保存 CPU 記憶；模型權重包含 CPU、記憶體與 32 KB PRG-ROM，PPU、控制器、APU 暫存器與部分時序則留在 host 程式中。

公開 checkpoint 的架構是 `Qwen3_5ForCausalLM`，有 7 層 Gated DeltaNet 與一層全零 attention layer；bf16 參數量為 466.6M，檔案約 933 MB，其中 9.3M 個參數為非零。專案提供 `run`、`check` 與 `trace` 指令，並附有權重 checksum 與測試程式。

作者用官方 nestest、Thwaite 與一款完整遊戲進行比對。README 列出的結果包括 nestest 的 4,586 tokens 以預期 HALT 結束、Thwaite 600 frames 的 300 張保存畫面全部相符，以及完整遊戲 420 frames 的 210 張保存畫面全部相符。執行速度仍比真實 NES 慢約 150 到 290 倍；README 估計，在一般執行模式下每幀可能需要 1 到 6 秒，600 frames 約需 25 分鐘。

目前限制包括只支援 NROM（iNES mapper 0）卡匣、只處理官方 opcode、沒有 IRQ、沒有聲音，PPU 的 sprite-0 hit 與 sprite overflow 也只是近似。這個專案展示的是一個可檢查的權重內電路實作，不代表 Qwen3.5 在一般推理任務中學會了 NES 模擬器，也不代表模型生成文字時能取代專用 CPU。

- 來源：[github.com](https://github.com/dbreunig/nesformer)
