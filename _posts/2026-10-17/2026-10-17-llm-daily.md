近三天的新消息集中在同一種工作方式：把模型放進有明確規則、可執行驗證與可量化成本的流程裡。Anthropic 展示 Claude 參與密碼學參數考證、量子電路設計與大規模程式碼審查；另一個開源專案則把 GGUF 模型搬到越獄 PS5。這些案例的結果都依賴特定的 evaluator、硬體、權限或測試設定，不能直接等同於一般用途的模型能力。

## 🔥 Claude 追出部分 ECDSA 曲線參數的生成方式

Anthropic 發布研究，說明 Claude 如何協助追查 NIST 與 ANSI X9.62 橢圓曲線參數中長期未解的 seed 來源。研究團隊讓模型從既有的 seed 數值與歷史線索出發，測試 1990 年代 C 函式庫的偽隨機數產生器；模型辨識出 `lrand48` 輸出留下的位元模式，再利用狀態回復與格基約化方法重建內部狀態。

研究表示，10 組 prime-curve seed 都可由以 Unix timestamp 初始化的 `lrand48` 重新產生，4 組 binary-curve seed 也呈現相同產生器的模式。Claude 另找出 6 條較早曲線的 base point 可由 FreeLIP 的隨機數產生器與特定整數 seed 重現。Anthropic 提供 Python 程式碼供讀者重跑，並表示將 36,864 美元獎金捐給 Internet Security Research Group。

這項結果沒有解釋所有參數：B-163 的 seed 仍未找到來源，P-224、P-256、P-384 與 P-521 的 base point 也尚未被重建。文章把結果描述為降低蓄意植入弱點的可能性，但未宣稱這是對 ECDSA 的密碼分析攻擊；曲線參數仍需依照原有標準使用與驗證。

- 來源：[anthropic.com](https://www.anthropic.com/research/ecdsa-curve-origins)

## Claude 在八項量子電路任務中提出較低資源設計

Anthropic 表示，研究團隊把八個量子電路的自然語言規格交給 Claude Mythos 5，並提供會檢查正確性、量測 qubit 與 gate 數量的自動 evaluator。模型在閉環流程中提出程式、取得分數，再修改下一版；研究方稱它在化學、最佳化、物理模擬、數論與數值計算任務中，找到比既有發表設計使用更少 qubit 或 gate 的方案。

其中一項 elliptic-curve point addition 任務，Claude 在幾乎沒有人工介入的情況下運行 53 小時，提出不儲存完整 branch history、改由目前數值狀態解碼歷史的新方法。研究方表示，這套設計相較最小的既有方案多使用 12% qubit，但 gate 數量少 17 倍。另一項 Reed–Solomon decoder 設計改用 Berlekamp–Massey 方法，並以 4.03 億次模擬估計例外值的儲存需求；結果將 gate 數量降至 Google 先前設計的約十二分之一，但約萬分之一的樣本需要超過預留空間而失敗，仍在任務允許的錯誤率內。

這些數字來自研究方指定的電路、評分器與錯誤容許條件，且量子電路尚未在實際容錯量子硬體上執行。Anthropic 也記錄模型會反覆檢查結果、偏好既有方法，研究者因此要求它平行探索不同方案並偶爾擴大搜尋範圍。

- 來源：[anthropic.com](https://www.anthropic.com/research/designing-efficient-quantum-circuits)

## Claude Code 團隊把程式碼審查拆成自動檢查、風險分級與快速回滾

Claude Code 團隊公開內部程式碼審查流程。文章表示，Claude Code 的程式碼產量增加後，團隊把多數 diff 閱讀交給自動化檢查，讓人工時間集中在架構、風險、是否該建置，以及對結果負責等決策。每個 pull request 會先經過 CI、Claude review、獨立安全審查與風險分級；低風險變更可不需要人工核准，中風險需要一人，高風險或指定路徑需要兩人。

團隊稱，Claude Code repository 在 6 月至 9 月合併的 pull request 超過翻倍，而需要 revert 的比例下降超過 40%。內部資料也顯示，調整審查收斂流程後，一次 review 與修正即可通過的 PR 比例由 65% 升至 78%，需要五輪以上的比例由 8.9% 降至 1.5%，平均審查輪數由 2.08 降至 1.32。

流程仍保留多個人工與復原條件：安全審查有未結案 finding 時不能合併，新的行為先以 feature flag 給 Anthropic 員工使用，再逐步發布；作者與 on-call 也要監看並能快速回滾。文章承認團隊尚未建立在 revert 或 incident 數字上升時自動收緊核准要求的 circuit breaker，且較寬鬆的審查路徑只開放給信任的作者與指定風險等級。

- 來源：[claude.dev](https://claude.dev/blog/solving-code-review-at-anthropic/)

## 開源專案 PS5LM 讓越獄 PS5 執行 GGUF 模型

GitHub 專案 PS5LM 把 llama.cpp 與 ggml Vulkan 移植到越獄 PlayStation 5，讓主機 GPU 載入 GGUF 模型並透過區域網路提供 API。專案 README 列出的測試數據中，PS5 Slim 執行 Qwen 3.5 0.8B Q4_K_M 約每秒 207 tokens，9B 版本約每秒 55 tokens，27B 版本約每秒 20 tokens，後者使用約 9.2GB 模型檔並支援 64K context。

PS5LM 也支援 OpenAI 相容的 `/v1/chat/completions`、Anthropic 相容的 `/v1/messages`，以及用於一次 forward pass 分類的 decision model。README 列出 Qwen 3.5 9B 在 PS5 Slim 上回答筆電請求的展示，並提供主機溫度、功耗與負載監測介面；專案以 GPL-3.0-or-later 授權，未包含 Sony SDK、金鑰、韌體或模型權重。

使用條件不是一般零售 PS5：目前需要 7.00 至 13.60 韌體、越獄主機，以及 kstuff-lite、etaHEN、ShadowMountPlus 等 payload。專案列出的速度與模型支援範圍是作者 README 的測量，實際結果還會受主機型號、量化格式、context 長度與 Vulkan 移植狀態影響。

- 來源：[github.com](https://github.com/cobanov/PS5LM)
