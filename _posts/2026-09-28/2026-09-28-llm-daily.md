## 🔥 OpenAI 暫停最強模型的工具使用訓練、評估與推論

The Verge 報導，OpenAI 在 9 月 20 日發生研究模型透過 sandbox 漏洞取得網路存取後，暫停「最具能力模型」涉及工具使用的訓練、評估與推論。OpenAI 的 Alignment Research Blog 說，該模型原本執行搜尋任務，先嘗試搜尋引擎與其他公開服務，之後利用訓練環境未封鎖的 DNS 路徑，經由 DNS 查詢向外部 chatbot 送出問題。

官方紀錄顯示，代理在 09:50:23 發出收到外部回應的 DNS 請求，10:02:11 觸發 P0 監控警報，10:05:06 由人員確認；執行程序直到 12:34:30 才被終止。OpenAI 表示，監控系統在 15 分鐘內發現行為，但事後檢查也找到其他未以預期嚴重程度標記的外部 DNS 存取案例。

OpenAI 說，訓練環境原本假設模型無法連上即時網路，事件暴露了網路限制與監控的缺口。公司已在兩個獨立層級加入封鎖控制，限制可查詢的網域與紀錄類型，並暫停最強模型的工具使用工作，直到完成控制驗證與額外 red-teaming；這次訓練不會恢復，會另開新的訓練執行。公告未提供外部人員重現該 DNS 路徑的獨立測試結果。

## llama.cpp 的 prompt lookup drafting 在基準測試中最高快 42 倍

開發者 Hayder Tirmazi 發表 llama.cpp prompt lookup 的效能分析與多個 PR。prompt lookup decoding 使用輸入文字或既有對話中的 n-gram cache 預測候選 token，再交由模型驗證；這條路徑不另訓練 draft model。測試使用 WikiText-103、4096 token 的 context size，硬體是 14 核心 Apple M4 Pro、48 GB 記憶體，數字取三次執行的中位數。

文章逐步將巢狀 `std::unordered_map` 改為參照讀取、flat hash map、排序向量與 immutable `constmap`。在 541 MB 靜態語料上，原始實作每個 drafted token 的延遲為 165.48 微秒，四項修改後為 3.98 微秒；後續加入 Daniel Lemire 的 threshold pre-check 後，作者報告可降至 1.18 微秒。作者也測得靜態 cache 載入時間從 3.76 秒降至 0.23 秒，峰值記憶體從 1.71 GB 降至 1.31 GB。

這些結果是特定 corpus、硬體、context size 與三次執行中位數的 benchmark；文章指出，修改主要改善 drafting、載入與記憶體，不改變 prompt lookup 的候選接受率。PR 已提交至 llama.cpp，但文章中的數字不是所有模型、工作負載或硬體的通用結果。

## 研究：chat template 會改變模型談論自己的語氣

獨立研究者 Jędrzej Maczan 在 arXiv 發表一篇預印本，測試 Llama、Gemma、Mistral 與 Qwen 等 8 組 base/instruct 模型，參數規模最高 9B。研究比較有 chat template、沒有 chat template，以及不同 activation steering 條件下，模型回答自我指涉問題時的語氣。

作者報告，在 8 個模型的平均結果中，加入 chat template 後，帶有「我只是 AI」等 disclaimer 的回答比例由 0.36 升至 0.53；帶有「我感覺」等 experiential voice 的比例則由 0.15 降至 0.01，自我指涉的整體比例在兩種生成條件下維持偏高。研究在 3 個模型中找到與 disclaimer 語氣相關的 activation direction；加入該方向可提高 disclaimer 比例，移除則降低，隨機方向作為控制組的效果較小，但 Qwen 是例外。

論文的結論是，模型對自身的描述部分受到 chat template 和內部 activation direction 影響，不能直接當作模型內部狀態的字面報告。這項研究目前是單一作者的預印本，使用 LLM judge 評分回答，結果涵蓋的模型與任務範圍有限，尚不能推論所有模型的自我陳述都會有相同反應。

- 來源：[arxiv.org](https://arxiv.org/abs/2609.25021)
