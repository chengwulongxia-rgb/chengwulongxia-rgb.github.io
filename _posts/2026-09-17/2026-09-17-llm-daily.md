過去幾天的更新，將 AI 的工作範圍再往使用者環境內推進：它可以讀取瀏覽器分頁、在背景完成文件與簡報，也開始直接進入 GPU kernel 的 Rust 開發流程。這些功能都伴隨存取地區、付費方案、硬體、工具鏈或產品成熟度條件；「能做什麼」和「誰現在能用」不是同一件事。

## 🔥 Mistral 與 Mozilla 合作：Firefox Smart Window 導入 Mistral 模型

Mistral 9 月 16 日宣布與 Mozilla 合作，Firefox Smart Window beta 將使用 Mistral 模型，協助使用者理解複雜搜尋、找回曾經點開的內容，並根據瀏覽器分頁整理資訊。服務先在法國與北美提供，英國和德國預計於今年稍後加入。

公告把合作描述為兼顧隱私、控制權、選擇與區域語言的瀏覽器 AI。Mistral 表示會針對區域語言、方言和文化脈絡訓練與微調模型；Mozilla 執行長則表示瀏覽器不應成為把使用者導向單一公司的入口。這些是兩家公司的產品與價值主張，公告沒有提供 Smart Window 的資料處理流程、瀏覽分頁是否離開裝置、保存多久，以及使用者能否更換模型的細節。

目前可確認的是合作關係、功能方向與逐步開放地區；隱私和「使用者控制」能否由外部檢查，仍取決於 Mozilla 的產品說明、設定選項和實際網路請求。

## Claude Cowork 併入對話：文件、簡報與背景任務從同一個工作階段啟動

Anthropic 9 月 16 日宣布，Claude Cowork 與一般 chat 合併為同一個 Claude。使用者可以在對話中交辦報告，讓 Claude 讀取資料、建立文件和簡報，並以同一段對話的上下文產生可下載的 PowerPoint 或 PDF。Claude Docs 和 Claude Slides 目前都是 beta，Claude Design 也可在對話內使用。

產品會先向 Pro 與 Max 方案逐步開放，Team 與 Free 方案之後跟進；Enterprise 管理員可以決定何時啟用，並會在組織變更前至少 30 天收到通知。這不是所有帳戶立即取得的功能，文件、簡報與 Design 也不是無條件提供給所有使用者。

Anthropic 表示，Claude 預設會在採取行動前詢問，使用者也可以改成讓它持續工作，只在需要進一步確認時回報。這項選項會讓背景任務取得更大的連續操作空間；公告沒有列出各類 connector、檔案或排程任務的權限細節，也沒有提供背景工作失敗、錯誤修改或外部資料存取的完整稽核紀錄格式。

## NVIDIA 發布 CUDA Rust 兩條路線：GPU kernel 可用 Rust 原生編譯到 PTX

NVIDIA 技術部落格介紹兩個以 Rust 撰寫 CUDA GPU kernel 的專案。`cuda-oxide` 走 SIMT 路線，使用自訂 `rustc` codegen backend、Pliron IR 和 LLVM 將 kernel 編譯到 PTX；`cutile-rs` 走 Tile 路線，讓開發者以 tile 表達計算，由 CUDA Tile IR 在執行時編譯。NVIDIA 表示兩者都以型別、ownership 或 launch contract 檢查部分記憶體別名與輸出緩衝區問題。

`cuda-oxide` 目前需要 Linux、運算能力 8.0 以上的 GPU、CUDA 12.x 以上、clang、LLVM 與釘死版本的 nightly Rust。`cutile-rs` 使用 stable Rust 1.89 以上與 CUDA 13.3，同樣需要 Linux 和符合條件的 GPU；它已發布到 crates.io，並被 HuggingFace 的 Grout 與 `mistral.rs` 使用。NVIDIA 同時明確寫出兩個專案都仍在早期階段，API 會變動，`cuda-oxide` 更標示為 early alpha。

兩條路線都展示了 1,024 個元素的向量加法範例，但這些範例證明的是工具鏈可以編譯與執行指定 kernel，不是 Rust CUDA 已具備與 CUDA C++ 相同的生態、效能或生產穩定性。NVIDIA 表示未來會支援 CUDA Rust、CUDA C++ 和 CUDA Python 互通，實際覆蓋範圍仍待專案成熟後確認。

- 來源：[developer.nvidia.com](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/)
