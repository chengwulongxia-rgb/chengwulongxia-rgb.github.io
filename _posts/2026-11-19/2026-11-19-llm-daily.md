過去三天的新素材集中在模型如何完成長流程工作：Google 發布可用於程式、分析與科學工作的 Gemini 4 Neon；研究者以能量函數控制遞迴推理的修正、停止與候選選擇；OpenAI 則公布模型參與生產晶片與開源 RISC-V 核心的設計測試。以下分開說明官方 benchmark、研究者實驗與實際部署案例，並保留測試設定與開放條件。

## 🔥 Gemini 4 Neon 開放 API，Google 報告多項代理與科學 benchmark

Google 11 月 18 日發布 Gemini 4 Neon，提供 100 萬 token 上下文視窗。API 定價為每百萬輸入 token 3 美元、cached input 0.15 美元、輸出 15 美元；目前透過 Google AI Studio、Gemini for business、Google Antigravity 與 Gemini app 推出，部分入口需要付費 Google AI Pro 或 Ultra 訂閱。Google 也說，Neon for cyber 將在接下來幾天透過 Fairwind Program 向可信防禦者開放，並非一般帳戶同步取得。

Google 引用 Artificial Analysis Intelligence Index，稱 Neon 在 xhigh thinking 設定得分 61、排名第三；在 Vals Index 得分 70.9%、排名第二。公告另列出 Terminal-Bench Science 70.5%、RiemannBench 84.0%、HLE-Diamond 71.3%，以及 Agents' Last Exam v1.1 的 75.8%。這些數據來自 Google 公告所列的外部評測與設定，頁面沒有在同一處提供完整的獨立重現流程。

在程式工作上，Google 報告 Neon 在 Artificial Analysis Coding Agent Index 得分 58.6、Terminal-Bench 4.1 得分 65.2%，並稱在 Google Antigravity 的 SWE-sweep 測試中，使用該 harness 後得分由 mini-SWE 的 12.8% 提升至 39.0%。這組比較同時改變了執行 harness，不能只解讀成模型本身的差異。

Google 也表示 Neon 在高 thinking 設定下，每項任務成本比 Gemini 4 Carbon 低 32%；在部分第三方 benchmark 的成本約比其他 frontier model 低 50% 至 80%。公告未把這些成本數字延伸為所有工作負載的價格或延遲保證。模型卡片、資安測試的完整條件，以及 Fairwind Program 的審核與存取標準，另由 Google 的文件與計畫頁說明。

- 來源：[Google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)

## Energy-Based Reasoners 以能量函數控制遞迴推理

Energy-Based Reasoners（EBR）是 William Chen、Alexi Gladstone、Zeyu Li、Heng Ji 與 Yilun Du 提出的模型，程式碼與論文連結均放在專案頁。方法為遞迴模型學習一個能量函數，對目前的 latent state 與輸入計算相容性；模型沿能量梯度修正狀態，當梯度低於門檻時停止，並從多條軌跡選擇能量最低的候選答案。

在作者列出的 Sudoku-Extreme 與 Maze-Hard 測試中，1.8M 參數的 EBR 單一樣本準確率分別為 99.4% 與 87.4%。使用五個樣本時，數值分別為 99.9% 與 88.3%；作者以 GRAM 論文中的基準及已發布 checkpoint 比較，並說明結果是三個 random seeds 的平均與標準差。

作者報告，自適應停止在維持 99.9% 準確率時，相比固定深度 EBR 減少 10.9 倍 FLOPs；相對 EqR 的比較則寫為使用少 345 倍 FLOPs。這些數字來自 Sudoku-Extreme 的特定測試與推理設定，不等於一般語言模型或所有推理任務的效率比例。

在多解問題上，EBR 以 20 個樣本計算不同有效解的覆蓋率；專案頁列出 8×8 N-Queens 為 98.1%、10×10 Graph Coloring 為 92.0%，並另外列出 8 與 10 頂點圖形著色的覆蓋率。這項方法目前展示的是結構化謎題與圖形問題的實驗，頁面未提供自然語言生成、長上下文或生產代理工作流的結果。

- 來源：[Energy-Based Reasoners](https://energy-based-reasoners.github.io/)

## OpenAI 報告模型參與 Jalapeño、AMD 與 RISC-V 晶片設計

OpenAI 11 月 18 日公布模型協助晶片設計的後續結果。公司說，模型對其 Jalapeño 推論晶片的 vector unit 與 matrix unit 提出修改，估計標準元件面積分別降低約 13% 與 10%；其中部分改動已在 Jalapeño 的 silicon bring-up 中驗證。OpenAI 也列出單一 multiplier 綜合後面積約少 15%、延遲由兩個 clock cycle 降為一個，以及另一個 adder 面積約少 15% 且維持兩個 cycle 的案例。

在與 AMD 的合作中，OpenAI 表示相對於已高度最佳化的基線，模型在旗艦 GPU IP 的 PPA 最多改善 14%。AMD 已將部分改動放入送製造的設計，另一些改動放入未來版本的 production design files。OpenAI 表示 AMD 也在下一代旗艦 CPU 的關鍵區塊驗證了個位數百分比的 PPA 改善；公告沒有公開完整的 RTL、基線設計或各區塊的逐項數據。

OpenAI 以兩個開源 32-bit RISC-V 核心 PicoRV32 與 Ibex 測試模型能力。測試同時檢查模擬輸出、面積上限、隱藏 workload 的每時脈指令數與 Yosys 估計的最高頻率；失敗檢查或面積超過原核心 16 倍的設計計為零。在約 112,000 token 的可比預算下，OpenAI 報告 GPT-6.2 Astra 在兩個核心的既有設計最佳化平均分數最高，GPT-6.1 Sol 也高於 GPT-5.6 Sol。

另一項測試只提供書面規格與連接模板，讓模型從規格設計核心。OpenAI 報告五個模型在兩個核心上都比修改既有設計得到更高分，完整評估共計 9,881 次計分執行；公司同時指出，從規格設計的模型可能省略 performance counter 或額外指令等原核心功能，且測試尚未加入實體合成後的 timing 檢查，因此仍與生產晶片設計有差距。

- 來源：[OpenAI](https://openai.com/index/advancing-chip-design-with-our-models/)

## LLM 輔助逆向工程：以記錄假設與實驗追蹤二進位檔分析

Slow Chronicle 作者 ioma8 分享以 DeepSeek Harness、DeepSeek v4.1 Flash、Ghidra、Ghidra MCP bridge、radare2 與 kuna 進行逆向工程的工作流程。作者先判斷二進位檔類型、平台與 build，再要求 agent 將分析結果寫入 Markdown；接著整理主要函式、分支與 imported functions，必要時使用 debugger、breakpoint、logging、probe 或可控制的 emulator。

文章描述的 hypothesis debugging skill 要求 agent 把對系統運作方式的假設寫入 CSV，為每個假設設計可證明或否證的實驗，記錄結果後再進入下一輪。作者也會閱讀整段 LLM 對話與思考紀錄，在 agent 對某條分析路徑陷入狹窄方向時改變指令。

作者列出過去六個月的個人專案，包括分析 Alphasmart NEO、映射 EmWave 與 Sony Alpha 相機的通訊協定、替多種合成器製作 custom firmware，以及修改電子書閱讀器與印表機驅動程式。這是單一作者的工具配置與案例記錄，沒有提供對照組、完成時間的原始紀錄或可推廣到其他逆向任務的成功率。

- 來源：[Slow Chronicle](https://www.slowchronicle.com/posts/llm-assisted-reverse-engineering)
