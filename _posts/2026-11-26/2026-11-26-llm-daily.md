## 🔥 PenGPT 以小型 Transformer 生成筆跡與草圖

Sam Greydanus 發表 PenGPT，包含兩個模型：6M 參數模型根據文字生成印刷體與草寫，54M 參數模型根據文字提示生成草圖。作者把筆畫離散成八個方向加上落筆、抬筆等符號，再用 byte-pair encoding 合併常見的移動序列；手寫與繪圖使用同一套 tokenizer，繪圖模型另接收 SigLIP 2 向量。

手寫資料由掃描頁面建立，包含 1,255 位書寫者的 495,590 個單字；視覺語言模型先篩選與轉錄頁面，再由 InkSight 回溯筆畫，經檢查後約三分之一至一半的單字保留。繪圖資料包含十個公開資料集的 477,670 張草圖，Quick, Draw! 則只取其中一部分。作者沒有公開資料集，但在論文附錄說明建立方式，並公開程式碼與模型權重。

在作者報告的測試中，PenGPT 手寫樣本的 OCR 完全讀對率為 54%，真實墨跡為 66%；繪圖樣本對應提示的辨識率為 76%，對應 caption 的辨識率為 43%。模型能混合部分概念，但對物件關係與方向的控制有限；例如「面向左」與「面向右」的文字向量相似度為 0.999。這些數字來自作者設定的資料集、評測器與抽樣方式，不代表一般手寫或圖像生成任務的準確率。

- 來源：[Sam Greydanus](https://greydanus.github.io/2026/11/12/pengpt/)

## Anthropic 參與的 Lean 專案縮短廣義黎曼猜想形式化證明

GitHub 專案 `lsernau/grh-lean` 提供 Lean 4 形式化的黎曼猜想，以及 Dirichlet L-functions 的廣義黎曼猜想證明。README 表示，證明以 Levent Alpöge 的工作為基礎，與 Anthropic 同事及 Claude 合作完成；專案只使用 `propext`、`Classical.choice` 與 `Quot.sound` 三個公理，並建立在 Mathlib 上。

專案分成約 300,000 行的可讀版本，以及約 76,000 行、包含相同五個定理的 compact 版本。建置需要 Lean 4.35.0 與指定的 Mathlib commit；README 估計在 12 核心、24 GB 記憶體的機器上建置需一至兩小時，缺少 Mathlib cache 時還會增加約 85 分鐘。

README 將專案標示為研究成果、不維護且不接受貢獻，並明確寫出證明目前只通過機器檢查，沒有數學家完整讀過，也沒有隨附論文。機器能通過 Lean 的檢查，與數學界完成對證明內容的審閱，是不同的狀態。

- 來源：[GitHub：lsernau/grh-lean](https://github.com/lsernau/grh-lean)

## Claude 協助把 Rockbox 移植到 512 KiB 的廉價 MP3 播放器

Jayden Milne 記錄以 Claude 協助將 Rockbox 移植到一台售價 9.71 美元、使用未公開晶片的 YP3 MP3 播放器。裝置採雙核心 Cortex-M4、192 MHz、2 MB flash 與 512 KiB SRAM，Rockbox 移植後可啟動並播放音訊；由於播放器與外掛共用 128 KiB 記憶體區域，啟動外掛時會停止音樂播放。專案也移除了語音、專輯封面、背景圖片與多種其他功能，資料夾、播放清單及主題同樣有容量限制。

作者先以 Ghidra MCP 讓代理拆解韌體，透過 bootloader 模式注入 FreeRTOS 工作、探測硬體並撰寫驅動程式，再以乾淨室流程重新整理硬體事實與驅動程式。測試環境包含攝影機、麥克風、音源輸入、Bluetooth 介面，以及能讓播放器自行重開、刷寫、截圖與執行隨機按鍵測試的雙向開發介面。作者表示，另一台 TS17 播放器從接上裝置到可用 alpha build 約花四小時，但這是個人專案紀錄，不是受控的代理效能評測。

這次移植後加入的功能包括 Bluetooth HAL、數百個遊戲與外掛，以及一個約 100 萬參數、從 SD 卡串流權重的 RockGPT；文章沒有提供 RockGPT 的獨立能力評測。作者也指出，硬體逆向工程仍有需要人在場的部分，例如關機流程與 FM 收音機的時脈錯誤，並不是所有問題都能由代理在無人介入下完成。

- 來源：[Jayden’s Blog](https://jayd.ml/2026/11/14/rockbox-on-yp3.html)

## Engram 以資訊量估算 LoRA 所需 rank

Engram 發表一套估算 SFT 資料集所需 LoRA rank 的方法。文章把資料集在基礎模型下的負對數似然轉換為 bits，再以低秩 adapter 能儲存的資訊量估算容量；其理論模型預測，rank 增加時容量先近似線性成長，之後因奇異值下降而趨於平台。

在 Qwen3.5-0.8B 的 512×1024 `v_proj` 矩陣上，文章估計完整 rank 的容量約 378k bits；低 rank 時，每個 LoRA 參數約可儲存 1.4 bits。實際訓練多個層時，作者觀察到每個參數的容量從單層約 1.5 bits 增至 24 層約 3.3 bits，並將這種跨層效應稱為 super-additive。文章也報告，在測試的設定中，依資料集 bits 預測 rank，與實際能儲存 95% 資料集的 rank 誤差可控制在約 5% 內。

方法以 Qwen3.5-0.8B 等基礎模型、合成固定 bits 的資料與多個公開資料集進行實驗；作者說明，完整 Transformer 的非線性行為無法由單一矩陣理論直接預測，因此使用實驗曲線校準。文章的結論是可依資料集大小動態配置最小 PEFT adapter，但這項估算仍受基礎模型、採用的層、訓練步數與資料分布影響，不能視為所有模型與微調設定的固定換算表。

- 來源：[Engram](https://engram.com/blog/lora-size)
