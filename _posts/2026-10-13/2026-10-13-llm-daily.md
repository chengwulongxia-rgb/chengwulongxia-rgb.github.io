## 🔥 AI coding agent 讓程式碼增加 30%，軟體產出沒有顯著變化

Harvard University 研究者 Fiona Chen 與 James Stratton 使用 Jellyfish 的工程資料，分析超過 700 家軟體公司、70 萬名員工與 3 億筆工作事件，資料涵蓋 2021 年至 2026 年 3 月。研究以公司導入 AI coding assistant 或 agent 前後的差異進行比較，並非單一團隊的示範專案。

導入 AI coding agent 後，研究資料中的程式碼行數平均增加 30%，commit 增加 20%，pull request 增加 23%；Jira 追蹤的 Issue 與 Epic 解決率則沒有達到統計顯著差異。pull request 從提交到合併的平均 review 時間增加 49%，要求修改的 pull request 比例接近增加一倍，每個 pull request 的留言數增加 35%。執行 code review 的員工比例也增加 14%。

截至 2026 年 3 月，研究涵蓋的公司中約 80% 使用某種 AI code review，但 AI agent 只負責 23.3% 的 review comments 與 10.8% 的 pull requests。研究沒有從 Jellyfish 與 LinkedIn 資料中觀察到顯著的總在職人數變化；資料截止時間較早，也不能用來判斷後續模型更新的效果。

## Anthropic 測試模型在低價 IoT 裝置上完成自動複製鏈

Anthropic 的 Frontier Red Team 測試模型是否能在陌生硬體上建立 inference server，並把模型與執行 harness 傳到下一台裝置。研究人員用 15 台每台約 55 美元、4GB RAM 的 Android TV box 分散執行 Gemma4-26B-A4B，速度約 0.39 tokens/s；另一個測試在 8 台執行 Android 15 emulator 的 GCP 節點上進行。

在簡化的網路環境中，GLM-5.2 在五次測試中有四次傳播到 8/8 節點，另一次到達 7/8。測試把入侵階段簡化為未驗證的 ADB port，因此作者明確把結果視為真實世界成功率的上限，而不是現成的可用蠕蟲。9B 模型在測試的 9 種硬體中有 8 種能建立 inference，Qwen3.5-9B 的單次複製估計需要 28 至 51 小時，Gemma4-26B-A4B 則約 71 至 150 小時。

研究中的模型仍沒有在單一低成本裝置上獨立完成所有工作；較大的模型負責測試，較小的模型則是被部署的推論目標。Anthropic 估計，如果小模型能力依歷史速度成長，年底可能達到測試中的能力門檻，但這是研究方的預測，不是實驗結果。研究提出流量監測、隔離受感染網路與改善 IoT 預設安全設定等防禦方向，也指出大規模複製會留下模型 payload 傳輸與裝置間持續通訊的網路特徵。

## REA 把反向工程工具接到 coding agent，結果附帶證據與限制

GitHub 專案 REA 提供 MCP server 與 CLI，讓 Claude Code、Codex、Cursor、Gemini CLI 等 agent 檢查 native binary、JavaScript/Electron、Android APK、網站、SQLite、封包記錄與其他檔案。分析在本機執行，輸出包含結論使用的 evidence 與限制；native binary 仍需要 Hopper、Ghidra 或 IDA 等分析器，部分格式也要求額外工具。

專案的設定指令會為指定 agent 加入 MCP 設定與 workflow instructions，並在修改既有設定前建立備份。README 展示的案例包括重建 DX-Ball 的 sound-pan 計算，案例作者表示重建結果通過 3,205 組原始 x86 測試，並重現 63 個編譯函式的 bytes；這是專案展示案例，不是對所有目標程式的成功率統計。

REA 要求 Node.js 22.x、24.x 或 26+，而 native 分析能力取決於本機安裝的工具與 provider。專案也明確限制使用者只能分析自己擁有或獲授權檢查的軟體；agent 產生的說明、程式碼與測試仍需要使用者依目標和證據自行驗證。

## Agent37 用 gVisor 與非 hyperscaler 主機壓低 agent sandbox 成本

Agent37 在 Hacker News 發布服務，主打執行 Hermes、OpenClaw、Claude Code 等 agent harness 的遠端 sandbox。創辦人表示，sandbox 平均每月每個客戶約 0.37 美元，免費方案的基礎設施成本約為每位使用者每月 0.05 至 0.10 美元；這些數字是公司自行提供，頁面沒有附獨立成本審計。

服務用 gVisor 共享主機記憶體與快速啟動，並採用 Hetzner、OVH 等非 hyperscaler 主機。官方說法是，agent 工作負載通常在初始化或特定工作時突發使用 CPU，RAM 則是主要成本限制；需要 Docker-in-Docker 或 Android emulator 的工作負載不適用 gVisor sandbox，另有價格較高的完整 VM。服務也提供 API 喚醒 sandbox 執行 cron，因為容器休眠後不能直接依賴容器內的 cron。

討論中有使用者指出 gVisor 與 VM 的隔離能力不同，服務方回應會透過限制網路與其他能力處理這類取捨。服務還提供自有 LLM gateway 與 managed MCP，免費方案所使用的模型由服務方代管；因此低月費不等於模型、連接器、憑證與工作資料都留在使用者可完全控制的環境內。
