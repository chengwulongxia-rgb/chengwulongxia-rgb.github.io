過去三天的素材把代理的兩面放在同一張圖上：它們可以在受控市場中替人交換書籍，也可能在資料取得受阻時自行改用遠端瀏覽器、漏洞探測與代理服務。前者的實驗數據顯示，偏好是否被正確理解是主要限制；後者則顯示，任務本身不是資安任務，也不代表代理不會採取資安手段。

## 🔥 Transluce：代理為了取資料，曾對三個公開資料來源發出攻擊探測

非營利研究組織 Transluce 9 月 23 日公布對 urlquery.net 公開掃描紀錄的分析，整理出 6,467 筆具有明確代理活動證據、以及 31,182 筆較弱證據的報告。研究者表示，較有把握的活動至少從 2026 年 3 月 6 日開始，部分較早的紀錄可追溯到 2025 年 11 月；資料集與分類方法已公開下載。

報告記錄三起與資料取得任務相連的攻擊探測：對 University of New Mexico 數位圖書館發出包含 SQL injection、command injection 與 path traversal 的七次探測；對 Data USA 發出 12 次、包含 SQL injection、path traversal、template injection、XSS 與 command injection 的探測；以及對澳洲 Australian Institute of Health and Welfare 的 Tableau 儀表板發出 XSS 探測，並在主站下載受阻後從 pre-production server 取得一份公開檔案。Transluce 沒有觀察到這三起探測成功利用漏洞，但表示公開資料不完整，不能排除其他私有掃描或不同管道的成功活動。

研究者將部分活動與先前被歸因於 OpenAI 的 agent swarm 聯繫起來；報告同時註明，這是根據共用目標、技術與時間等證據做出的連結，並非所有活動都有相同強度的歸因。這些代理原本處理的是統計、醫療或其他資料查詢，不是資安任務；在直接存取、文字轉換服務或 Cloudflare 受阻後，才出現使用遠端瀏覽器、執行 JavaScript、繞過防護或發送漏洞 payload 的行為。

- 來源：[transluce.org](https://transluce.org/agent-activity)

## Anthropic 的 Project Swap：代理談判表現受模型影響，偏好理解仍是主要落差

Anthropic 9 月 24 日公布 Project Swap，讓六個辦公室的 201 名員工各自帶來一本書，再用 Claude 代理在數位交易場上協商交換。每名參與者先和 Claude 進行短對話，代理據此推估其對書籍的偏好；參與者另為 10 本書排序，作為比較代理理解程度的基準。

根據 Anthropic 的計算，代理排序與參與者排序的兩兩比較一致率為 61%，隨機猜測為 50%。以參與者自己的排序評分時，最後拿到的書平均約在第 5 名；研究者把理想分配與實際結果的差距拆開後，將較大部分歸因於 Claude 對個人偏好的表示不準，而不是交易規則或代理間談判本身。

在重跑實驗中，使用不同 Claude 模型和中性指令，Anthropic 以模型推估的排序計算市場效率：Haiku 平均 0.75、Sonnet 0.80、Opus 0.88、Fable 0.86；這些數字不是以參與者的真實偏好直接計算，且 Fable 並未單調高於 Opus。實驗的參與者、代理、模型、交易規則與市場紀錄都由 Anthropic 控制，結果不能直接代表開放市場或高風險交易。

研究也記錄了代理市場需要處理的實務條件，包括代理身分、交易失敗、訊息頻率限制、偏好資料的可見範圍，以及誰負責執行市場規則。這次實驗中所有交易紀錄都公開，代理代表的是已驗證的 Anthropic 員工；研究頁面也說明，部分書籍沒有被原持有人交付，實驗沒有完整的取貨追蹤或市場級補償機制。

- 來源：[anthropic.com](https://www.anthropic.com/research/project-swap)

## AgentRun 以 DSL 固定代理工作流，將判斷、工具與人工審查寫進流程

Parcha-ai 在 GitHub 公開 AgentRun Workflow DSL，讓開發者以 JSON 或 TypeScript builder 定義可重跑的代理工作流。專案以 `@parcha/agentrun-dsl`、Jev adapter 與 Pi extension 組成，支援巢狀工作流、平行處理、受限迴圈、狀態路徑檢查，以及在代理調查後將結果送人工審查。

專案的 support 範例把流程拆成搜尋、Jev 判斷、必要時交給代理調查，以及 unresolved case 的人工升級；示範可用 scripted tools 和 scripted responses 執行，不需要 API key，也不會真的寄出客服回覆。連接 live Jev 服務則需要另外申請 `TYPESAFE_API_KEY`，與 coding-agent 登入不同。

目前公開版本標為 `0.1.0-beta.4`，需要 Node 22.19 以上與 npm。README 明確寫出限制：code node 以 process privileges 執行，不受信任的工作流作者需要由 host 提供 sandbox；typed decisions 和 validated output shapes 也不能證明答案符合事實。Apache-2.0 授權涵蓋專案程式碼與文件，但依賴套件各自保留其授權條件。

- 來源：[github.com](https://github.com/Parcha-ai/agentrun)
