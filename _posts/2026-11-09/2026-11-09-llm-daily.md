過去三天較新的素材，分別涉及模型能否由使用者自行部署，以及企業如何限制能夠執行程式碼的代理工具。Mistral 公布新模型的開放權重與自建部署方式；另一個 GitHub 專案則展示在沒有 GPU 的條件下執行大型 MoE 模型的工程取捨。Goldman Sachs 的案例顯示，企業內部是否開放代理，會按職務、地點與程式碼審查流程分開處理。

## 🔥 Mistral Large 4 開放權重，官方報告 Terminal-Bench 4.0 得分 41%

Mistral 發布 Mistral Large 4（Le Chonk）的模型權重。官方將它描述為 1 兆參數的原生多模態模型，提供 Low、Medium、High 三種 reasoning mode；權重可從 Hugging Face 下載，並以 vLLM 或 SGLang 在自有基礎設施部署。模型使用 Mistral Ecosystem Open-Weight license，官方 API 價格列為每百萬 input tokens 0.70 美元、cached input 0.07 美元、output 2.10 美元。

Mistral 表示，模型在 Cognition 的 private FrontierCode 2.0 得分為 19.7%；在 Artificial Analysis Coding Agent Index 得分 48%，平均每項任務使用的 tokens 比其比較中的領先 open-weight 模型少 47%。Terminal-Bench 4.0 的分數則為 41%，比公開預覽版高 13 個百分點，輸出 tokens 減少 30%。這些結果由 Mistral 引用外部評估或自身比較，公告沒有提供完整測試資料與獨立重現流程，不能視為所有程式工作流的固定表現。

資安部分，Mistral 報告 Artificial Analysis Cyber Index 得分 51%，並稱對惡意 cyber requests 的平均拒答率為 96.6%。官方同時說明，觀察到模型拒絕對真實目標進行的 black-box attacks，但仍看到執行真實攻擊的潛在提升，因此正在調整 guardrails。針對進階資安工作流的專用變體，目前只對企業 design partners 提供預覽，且須經審查與契約限制，測試限定於自有或明確授權的系統與受控環境。

## llama-modchip：專案聲稱以 64 GB RAM 執行 284B DeepSeek-V4-Flash

GitHub 專案 `llama-modchip` 發布 v2.4.0，展示以量化 GGUF 與修改過的 `llama.cpp` 執行 DeepSeek-V4-Flash 284.33B 模型。README 列出的模型檔案大小為 56.56 GiB，13.17B 個參數處於 active 狀態；在 AMD Ryzen 9 9955HX、64 GB RAM、零 GPU 的條件下，專案維護者記錄的峰值常駐記憶體為 57.61 GiB，256K context，prefill 速度為 43.16 至 44.36 tokens/s。

同一組結果列出純 CPU decode 約 9.06 至 10.74 tokens/s；啟用 Stockfish-PVS v2 的 speculative decoding 後，專案表格列出 11.50 至 14.69 tokens/s。README 也報告對 30B MoE 模型使用 Fractal-64 量化與 CPU kernel 調整後，部分設定可達 48.39 平均、60.40 peak tokens/s。這些是專案自己的硬體測試與 benchmark，並非模型發布方或第三方測試集的品質驗證。

專案把速度與記憶體結果歸因於 1.71 bpw 量化、AVX-512 kernel、MoE routing、KV cache 與自訂 speculative decoding；README 同時列出未修改量化檔在 64 GB 條件下會超出記憶體並使用 swap。要重現結果仍需相同或相近的 CPU、編譯版本、量化檔、啟用參數與 context 設定，且低 bit 量化對輸出品質的影響不能由 tokens/s 數字單獨判定。

## Goldman Sachs 依職務限制 Claude Code 與 GitHub 的使用

State of AI 引述 Bloomberg 報導，Goldman Sachs 在 10 月更新內部指引，將 Anthropic 的 Claude Code 與 Microsoft 的 GitHub 限制給工程師使用，多數銀行家與交易員不再能在工作中使用這些能讀檔、寫程式並執行程式碼的工具。跨交易、量化研究與軟體工程工作的 strats，據報仍可使用。Goldman 發言人表示，公司會提供部分 AI 工具，讓員工評估不同使用情境。

報導指出，交易員與銀行家先前用這些工具監看客戶交易流、建立市場模型，以及製作文字和圖表；Goldman 的資訊長 Marco Argenti 在 7 月曾談到非技術員工以 AI coding agents 建立工具，再交由約 12,000 名工程師改進。新的指引則把使用範圍按職務收回到工程團隊，理由包括生產力與風險審查。

Goldman 今年 4 月也曾因地點與合約條款，移除香港銀行家在內部平台使用 Claude 的權限；該限制與這次依職務限制第三方 coding agents 是不同條件。報導另指出，Goldman 仍使用由多家模型組成的內部 AI assistant，並與 Anthropic 合作建立交易會計與客戶 onboarding 的後台 agent；Goldman 同時是 Anthropic IPO 的主承銷商之一。這些資訊不能推導出 Goldman 全面停止使用 Claude，也不能把工程師可用的工具範圍套用到所有員工或地區。

- 來源：[State of AI](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers)
