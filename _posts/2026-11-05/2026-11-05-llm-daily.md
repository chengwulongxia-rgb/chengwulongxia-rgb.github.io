## 🔥 Google Gemini 個人帳戶的對話可用於改善服務與訓練模型

Hacker News 上一則使用者貼文指出，Gemini 個人帳戶在開啟 Keep Activity 時，聊天紀錄可被用於訓練，且部分內容可能交由人工審查；貼文同時引用 Google 的 Gemini 說明文件。這則貼文是使用者提出的提醒，不是 Google 對該個案的獨立確認。

Google 的官方說明寫明，Gemini Apps Activity 在 Keep Activity 開啟時，可用於改善 Google 服務，包括訓練生成式 AI 模型。Google 也說，部分互動、摘要、擷取內容與推論會由受訓服務提供者進行人工審查，並提醒使用者不要輸入不希望審查員看到、或不希望 Google 用來改善機器學習技術的機密資訊。

官方文件列出的控制方式是關閉 Keep Activity，以停止未來聊天被用於改善 Google AI；但文件也寫明，Keep Activity 關閉後，部分功能會受影響，例如某些 Connected Apps 不再可用，而聊天仍可能為提供服務、處理回饋或防止濫用而保留最多 72 小時。刪除 Gemini Apps Activity 也不會撤回已被人工審查的資料，且不會刪除其他服務已收到的資料。

這套條件適用於 Gemini Apps 的個人服務說明，不能延伸成企業方案或所有 Google 服務的統一資料政策。實際能否關閉資料改善用途，以及關閉後失去哪些功能，要看帳戶類型與當下設定頁面。

## Nvidia RTX Spark 原生 Linux 推論速度可能降至 Windows 的約五分之一

MindStudio 對搭載 Nvidia RTX Spark 的 MSI Prestige N16 Flip AI Plus 進行雙系統測試。文章表示，Linux 可以啟動並使用 Nvidia 的開放核心驅動與 CUDA，但接上電源後，GPU 時脈約被限制在 780 MHz；Windows 測試則約為 2.2 GHz。

在 GPT-OSS-120B 測試中，Windows 的速度為每秒 65.4 tokens，WSL 為 65.1 tokens，原生 Linux 為 13.9 tokens。以 vLLM 同時處理八個客戶端時，WSL 為每秒 127 tokens，原生 Linux 為 39.5 tokens。文章另報告，Linux 在未插電時可回到約每秒 61 至 67 tokens，插電後則降至約每秒 15 tokens；測試中的溫度約為 40 至 47°C，作者因此將問題與溫度節流區分開來。

作者將原因指向 Windows 裝置管理員中的 Nvidia Platform Controllers and Framework。這個元件管理 CPU 與 GPU 的共享功耗，Linux 目前無法讀取其中加密的電源設定表。文章記錄停用該控制器後，速度由約每秒 83 tokens 降至 31 tokens，重新啟用後恢復；這是單一硬體與測試環境的實測，不是 Nvidia 的官方故障公告。

文章的結論是，現階段 WSL 能保留 Windows 驅動的 GPU 行為，同時執行 vLLM、SGLang 等 Linux 工具；但 WSL 預設只配置約 14GB 記憶體，使用 128GB 統一記憶體的模型工作負載仍需手動調整。原生 Linux 的完整修正仍取決於 Nvidia 是否提供相應的電源管理支援。

- 來源：[MindStudio](https://www.mindstudio.ai/blog/linux-nvidia-rtx-spark-laptop)

## Anthropic 開源 FlashProve，為 LLM 回應加入可驗證推論證明

Anthropic 發布 FlashProve，目標是讓模型供應商對模型權重做承諾，並為回應產生零知識證明；持有承諾、提示詞與回覆的人，可以在不知道模型權重的情況下驗證回覆是否由該模型產生。Anthropic 同時公開技術報告、協定規格、C++ verifier、Lean verifier、Lean 證明與程式碼，採 Apache 2.0 授權。

Anthropic 以 400B 參數的 Llama 4 Maverick mixture-of-experts 模型測試。官方報告稱，在 4-bit 權重、每次 1,024-token 請求的設定下，單張 H100 產生證明約為每秒 110 tokens，證明檔約 19MB；與 vLLM 比較時，產生證明的 GPU 時間約為直接執行模型的 70 至 95 倍。驗證端使用 CPU，官方稱可在數秒內完成驗證。

FlashProve 採用事後證明，不是在模型輸出每個 token 的同時完成。這會增加重新計算、延遲與處理非決定性的問題；官方文件也指出，原型目前只對整數模型與 greedy decoding 提供證明，沒有隱藏模型架構，快速執行的 C++ 程式碼本身也沒有形式化保證。

Anthropic 將用途列為模型身分驗證、路由服務完整性、稽核與監管。這些用途仍取決於供應商如何管理模型承諾、證明產生器與驗證器；公開原型展示的是可運作的研究系統，不是已能以一般 API 成本部署的服務。

- 來源：[Anthropic](https://www.anthropic.com/research/provable-inference)、[FlashProve GitHub](https://github.com/anthropics/FlashProve)

## OpenAI 宣布收購 Pierre，將其 Git 與程式碼檢視工具併入 Codex

OpenAI 11 月 4 日宣布將收購 Pierre Computer Company。OpenAI 表示，Pierre 背後的 Trees 與 Diffs 函式庫已用於 Codex app，另外還有 Diffs 的 Edit 模式、Highlights 語法高亮工具，以及以 Git 追蹤程式碼歷史的 Code Storage 服務。

官方說明將收購目的描述為擴充 Codex 的建置、理解與檢視程式碼能力，並把開發者既有的 Git 工作流接到大量 coding agent 平行工作的環境。OpenAI 本週另公布內部 Git-compatible backend Pando，但本次收購公告沒有宣布 Pando 或 Pierre 工具對外提供的完整產品形態。

OpenAI 表示，Pierre 的開源專案在收購後會維持開源並繼續貢獻，Code Storage 的客戶在交易完成後仍可使用服務，之後再逐步把功能帶入 Codex。公告也寫明，交易須經一般交割條件與監管核准；完成前兩家公司仍維持獨立。

公告沒有提供交易金額、收購完成時間、Code Storage 後續服務條款或 Codex 產品整合時程。現階段可確認的是收購意向與承諾中的開源安排，不是已完成的產品合併。

- 來源：[OpenAI](https://openai.com/index/openai-to-acquire-pierre/)

## Mistral Large 4 開放權重，模型卡與基準數字仍由發布方提供

Mistral 發布 Mistral Large 4（Le Chonk）的開放權重，官方將它描述為 1 兆參數、多模態模型，並提供 Hugging Face 權重、模型卡、授權文件，以及以 vLLM 或 SGLang 自行部署的方式。官方頁面列出的 API 價格為每百萬 input tokens 0.70 美元、cached input 0.07 美元、output 2.10 美元。

Mistral 表示，模型在 Cognition FrontierCode 2.0 得分 19.7%，在 Artificial Analysis Coding Agent Index 得分 48%，Terminal-Bench 4.0 得分 41%；後者比公開預覽版高 13 個百分點，並減少 30% 輸出 tokens。這些數字來自 Mistral 頁面引用的基準與比較，模型版本、提示設定、評分流程與可重現條件仍需以各基準的公開資料核對。

在資安用途上，Mistral 報告 Artificial Analysis Cyber Index 得分 51%，並稱對惡意資安請求的平均拒答率為 96.6%。同一篇公告也寫明，公司在預覽期間觀察到模型可能提升真實攻擊能力，並調整 guardrails；供進階資安工作流使用的專用變體，目前只向經審查的企業夥伴提供，測試限於自有或明確授權的系統與受控環境。

開放權重代表使用者可以檢查、客製化與自行部署模型，但不等於上述基準已由外部獨立重現，也不等於模型在不同部署環境中會維持相同拒答率。Mistral 採用的是其 Ecosystem Open-Weight license，實際使用仍受授權條款與部署責任限制。

- 來源：[Mistral AI](https://mistral.ai/news/mistral-large-4-oss/)、[Mistral Large 4 模型卡](https://docs.mistral.ai/models/mistral-large-4-0)、[Hugging Face 權重](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B)
