過去三天的新素材有三個不同層次：研究者讓模型在沒有梯度更新的情況下修改自己的權重，開發者則讓 coding agent 連續數日完成 FPGA 推理實作與最佳化；同時，GPT-6.2 Astra 與 Sol 的價格和 benchmark 資料已出現，但早期使用者對 Astra 的實際表現並不一致。以下分開交代實驗設定、測試結果與尚未涵蓋的範圍。

## 🔥 27B 模型在無梯度訓練下改寫自己的權重

arXiv 論文〈Language Models Can Rewrite Their Own Weights〉提出 self-rewriting 流程：模型取得自己的權重、練習題答案與評分結果，透過 forward passes、程式碼及 hidden state 讀取來診斷失敗，再直接修改權重；流程沒有使用 gradient、optimizer 或另一個更強的模型。論文研究的是 Qwen3.5 系列，並測試 2B、4B、9B 與 27B 模型。

在一套讓模型先用保留練習題檢查修改的 protocol 中，27B 模型執行八次 session，其中三次提交修改、五次撤回。研究者把每次提交的模型與原始模型放在同一組 490 個未看過的題目上，每題八個答案：第 2 次修改的準確率由 57.2% 變為 61.3%，第 8 次由 57.2% 變為 63.8%，兩項差異的 permutation test 都是 p<10^-5。第 8 次修改也把答案在 16,384-token 上限前未完成的比例由 33.6% 降至 26.1%。

另一項實驗先破壞模型的一個權重區塊，再讓模型只根據文字任務中的統計結果修復它。修復前後在六個影像 benchmark、共 600 題的準確率由 7.3% 變為 70.2%，原始未破壞模型為 84.3%；論文表示影像題目在修復流程完成後才評估，session 沒有讀取影像資料。較小模型沒有產生修改，或產生的修改使模型失效；論文將能否自我修改與模型規模的關聯列為實驗結果之一。

這些數據來自單一模型家族、特定題目、token 預算與修改 protocol。論文也記錄過模型在較窄的樣本上先判定修改有效、再以較廣測試撤回的案例；因此研究展示的是一種可測試的權重修改流程，不是已證明可持續運作的通用自我訓練方法。

- 來源：[arXiv](https://arxiv.org/abs/2611.21885)

## Coding agent 在 AWS FPGA 上把 LLM 推理速度從 6.43 提升到 213.13 tokens/s

Ankit Gupta 記錄一項以 AWS F2 FPGA 執行 DeepGrove ternary-weight LLM 的實驗。作者讓 coding agent 在 Conductor 中連續工作數日，撰寫 C++ 與 Verilog、執行測試和合成，從第一個能逐 token 對齊的完整模型 baseline 開始，經 166 次提示與多輪實驗，把測得速度由 6.43 tokens/s 提升至 213.13 tokens/s。作者估計整段實驗產生約 300 萬行歷史程式碼與 3,000 萬行輸出，模型 API 費用約 10,000 美元。

最終 FPGA image 使用 AWS `f2.6xlarge`，在作者的 8-chat × 3-turn benchmark 中完成 24/24 個 exact turns。相同模型的 32-thread CPU twin 在 `m8a.8xlarge` 上為 129.5 tokens/s，FPGA 測得 213.13 tokens/s；兩者當時的每小時價格分別列為 1.98 美元與 1.95 美元。作者也列出 context 增長到 8,192 tokens 時的結果：r9 image 從短上下文約 233 tokens/s 降至 6–8k 區間的 76 tokens/s，完整長上下文執行時間為 77.8 秒。

文章記錄的最佳化包括 burst attention、平行 router、權重封裝、memory port 調整與 speculative decoding。作者指出，有兩個只在硬體上出現的 hang 讓整合工作多花了 38 小時；一次 soak test 也因在 231.25 MHz 發現隨機錯誤，最後改用較低時脈。文章中的 GPU 對照不是同等條件：列出的 T4 結果沒有全部逐 token 完成，作者因此沒有把它們當成 exact comparison。

這是單一作者的工程紀錄，不是對 coding agent 進行控制實驗，也沒有證明相同流程能處理其他模型、FPGA 或生產工作負載。作者明確寫道，該 8,192-token-context FPGA 架構不是他對生產部署的推薦方案。

- 來源：[Ankit Gupta](https://ankitg.me/blog/vibecoding-inference-chip/)

## GPT-6.2 Astra 與 Sol 的成本下降資料，早期使用者評價不一致

Latent Space 11 月 17 日整理 OpenAI 發布 GPT-6.2 Astra 與 Sol 後的資料。文章引用 Artificial Analysis 的測試，稱 Sol 在每項任務成本約為 9 月 Astra 的 15%；標題所列的比較範圍是 Astra 與既有 frontier models 的 benchmark 成本低 20% 至 600%。這些是第三方評測與價格計算，並非 OpenAI 對所有工作負載的成本保證。

文章同時整理 Agents’ Last Exam 1.1、長時間工程執行、3D 與 robotics、research agents 等測試連結，也列出 Astra 的 system card 與價格資料。Latent Space 引述的早期使用者回饋有明顯分歧：部分測試者回報可用於自動化工作，另一些則指出輸出行為與 reinforcement-learning artifacts，文章並附上相關貼文與影片作為來源。

OpenAI 在發布中將 Astra 與 Sol 定位於不同用途，但 Latent Space 的整理指出，單一 benchmark 排名、任務成本與實際工作流程中的穩定性並不等價。現有材料主要是發布資料、第三方測試整理和早期使用者回報，尚不足以推出兩個模型在所有程式、研究或代理任務上都具有相同的成本／品質排序。
