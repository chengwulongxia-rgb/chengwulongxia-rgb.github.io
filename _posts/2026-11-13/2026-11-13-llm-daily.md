過去三天的素材集中在模型如何被部署與驗證：Google 將 Gemini 4 Hydrogen 放進代理工作流，Apple 擴充跨模型的開發介面，研究者則從公開權重追查硬體痕跡。以下分開列出官方產品文件、開源專案與外部取證報告，並標示各自的測試條件與未知事項。

---

## 🔥 Gemini 4 Hydrogen：Google 將快速執行模型放進代理工作流

Google 於 11 月 12 日發布 Gemini 4 Hydrogen，定位是處理日常程式開發與 agentic workflow 的模型。官方列出的可用介面包括 Google AI Studio、Gemini API、Gemini for business、Gemini app、Google Search，以及付費 Google AI Pro 和 Ultra 訂閱者可使用的 Google Antigravity；免費 Gemini 使用者則會在開啟自動選模時，於系統判定適合的提示中取得 Hydrogen，並非每次都直接選用該模型。

Hydrogen 的公開 API 價格為每百萬個輸入 token 1.50 美元、輸出 token 7.50 美元，適用於一百萬 token context window。Google 引述 Artificial Analysis Intelligence Index，稱 Hydrogen 在預設 high thinking level 得分 51，在 xhigh 得分 54，高於該頁列出的 Gemini 4 Argon 50；這些數字是 Google 公告引用的外部評測頁結果，不是完整獨立重測報告。

Google 同時發布 Google Antigravity 的 Orchestrator，能在同一工作階段於 Gemini 4 Carbon 與 Hydrogen 等模型間切換。Google 表示，在 Terminal-Bench 4.0 測試中，Orchestrator 的任務成功率接近 Carbon，平均少用 24% quota，完成時間快 19%。公告沒有列出測試任務分布、失敗案例或 quota 計算方式，因此這些比例只適用於官方描述的測試設定。

Google 也報告 Hydrogen 相較 Gemini 3.8 Flash 在 Terminal-Bench 4.1 的分數由 18.2% 提升至 57%，高 thinking 設定下完成任務速度為 2.5 倍，並宣稱虛構內容減少超過五倍。公告展示多個 Google 產品中的程式與代理案例，但沒有提供跨工作流的獨立失敗率。安全部分則列出超過 200,000 個 audited turns、99.9% chain-of-thought legibility 與 Gray Swan IPI benchmark 2.3 倍韌性，詳細條件仍需對照 model card。

- 來源：[Google Blog](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)

## Apple Foundation Models framework：同一套 Swift API 可切換裝置模型與第三方模型

Apple 的 Foundation Models framework 提供原生 Swift API，讓應用程式使用 Apple 的 on-device foundation model，也能透過同一介面接入 Private Cloud Compute 與伺服器模型。Apple 文件列出的第三方支援包括 Claude、Gemini、Core AI Language Models 與 MLX Language Models；任何模型提供者都可以實作 `LanguageModel` protocol，支援 tool calling 與 guided generation。

這套框架也加入 Dynamic Profiles，開發者可在同一個 session 中切換模型、temperature、reasoning level 與工具組，並共享 session transcript。文件另列出 image understanding、Vision 的 OCR 與條碼工具、Evaluations framework，以及可用來建立 AI-powered scripts 的 `fm` CLI。Apple 也提供 Foundation Models framework utilities 與 Python SDK，但這些是另外的開源套件，不等於所有 Swift framework 功能都已在 Python 中提供。

Private Cloud Compute 的免費條件有明確資格限制：加入 App Store Small Business Program 且首次 App Store 下載量少於兩百萬的開發者，可以使用在 Private Cloud Compute 執行的 Apple Foundation Models，文件稱沒有 cloud API cost。Apple 同時註明，依賴伺服器模型的部分 Apple Intelligence 功能與開發者在 Private Cloud Compute 使用的模型可能有每日用量限制，限制會依功能、請求複雜度、系統需求與政策變動，未來擴充存取可能收費。

- 來源：[Apple Developer](https://developer.apple.com/foundation-models-framework/)

## MACaQ：Huawei 開源跨模型量化工具，支援 GGUF 與多種推論後端

Huawei Central Research Institute 的 `huawei-csl/MACaQ` repository 以 Apache 2.0 授權發布，主打 model-agnostic quantization，支援文字、影像、影片與音訊模型。README 列出的後端包括 llama.cpp、vLLM、Diffusers 與 PyTorch；文字模型可輸出 2、3、4-bit GGUF，也列出 W4A4 量化流程。

專案作者表示，MACaQ 可用 32.5 GB device memory 在 64 分鐘內量化 122B 參數模型，並稱相較另一個基線少 11 倍量化時間。README 也提供 Qwen3-4B 的檔案大小與 KL divergence 對照，以及 Qwen3.8-27B 的 perplexity、prefill 與 decode 數值；這些是 repository 維護者提供的專案結果，頁面沒有說明完整硬體、量化設定與獨立重現條件。

專案另提供 MACaQ-R，用來對既有 GGUF 做 refinement，並宣稱在相同 22.36 GB 檔案大小下，Qwen3.6-35B-A3B 的 KL divergence 由 0.015731 降至 0.013367。使用者仍需依後端分別建立 Python 3.12 環境；README 也說明 llama.cpp 可在 CPU 執行，其他工作流的硬體與相依套件則依各後端而異。

- 來源：[GitHub](https://github.com/huawei-csl/MACaQ)

## Unemployment Labs：公開模型權重出現 Blackwell 初始化指紋

Unemployment Labs 11 月 12 日發布一份取證分析，稱 DeepSeek、Moonshot AI、MiniMax 與 Ant Group 共六個公開模型的權重，呈現與 NVIDIA Blackwell GPU 初始化配置相符的指紋。報告分析的模型包括 DeepSeek-V4-Flash、DeepSeek-V4-Pro、Kimi K3、Kimi K3.1-Pro、MiniMax-M3 與 Ling-3.1-flash；研究方表示曾在實體 Blackwell 晶片上重現 DeepSeek-V4-Flash 與 Kimi K3 的匹配。

方法是從公開權重中尋找尚未被訓練改動或仍保留初始值痕跡的部分，再以不同 seed、GPU thread layout 與硬體配置重建。報告稱，Blackwell 的 148 或 152 個 streaming multiprocessors 配置能匹配這些模型，且 DeepSeek-V4-Flash 的測試結果在 1,385 sigma；作者也用已知硬體的 24 個案例做一致性檢查，表示分析結果與公開硬體說明相符。

這份報告把「初始化硬體可辨識」與「整個訓練都使用該硬體」分開。權重可以顯示建立初始值的硬體配置，不能單靠權重證明後續訓練使用的所有晶片、晶片所在位置、擁有者或取得方式。報告也指出，特殊配置的 AMD MI300X 可以重現 148 或 152 的 layout；DeepSeek-V4-Flash 的數值差異測試較支持 NVIDIA，但其他五個模型無法以同一測試排除 AMD 解釋。

研究方明確寫道，這些結果顯示的是硬體存取證據，不足以證明晶片位於中國或發生出口管制違規。分析所需的 reproduction scripts、row fixtures 與 test outputs，目前標示為可應審閱者要求提供，並非直接在頁面公開完整重現資料。

- 來源：[Unemployment Labs](https://unemploymentlabs.com/checkpoint-forensics)
