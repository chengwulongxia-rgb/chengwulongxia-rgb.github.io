過去三天的素材把 LLM 放進幾種不同的工作流程：協助人類編輯文章、嘗試解開第一次世界大戰的密碼、改造 Git 在物件儲存上的封裝方式，以及整理 IPO 法律工作。這些案例的證據層級不同，有些是作者的單次示範，有些是供應商或客戶案例；模型輸出的可用性仍取決於人工核對、測試條件與權限設計。

## 🔥 GPT-6 Astra 嘗試解開一組第一次世界大戰德軍無線電密碼

部落格作者 prinz 以一組 1918 年 11 月 27 日傳送、使用 ADFGVX 方法加密的德軍無線電訊息測試 GPT-6 Astra。作者指出，這組訊息屬於仍未解開的案例之一；其他數百則同類訊息已有研究者完成解碼，已知資料也包含部分德軍使用過的密鑰。

文章記錄 Astra 使用 `TRUPPENVERSCHIEBUNG` 作為密鑰，依照 J. Rives Childs 的德軍密碼史資料重建換位與方格，得到一段德文：`EIN ENGLISCHER KREUZER EINLIEG X SEWASTOPOL X S4STEN X EIN GESCHWADER DER X ALLIIERTEN FOLGT 26STEN X`。作者將其翻成「一艘英國巡洋艦於 24 日抵達 Sevastopol，盟軍中隊於 26 日跟進」，其中日期字元仍有不確定性。

作者再以海軍航行紀錄核對，指出 HMS Canterbury 在 1918 年 11 月 24 日抵達 Sevastopol，盟軍中隊在 11 月 26 日抵達。文章同時承認，作者不知道這則訊息過去是否已被其他人解碼；目前可確認的是一次由作者記錄的模型解碼示範，以及與公開歷史資料相符的交叉核對，並非密碼學界的獨立驗證報告。

## 以 LLM 做編輯器，而不是代筆者

A Final Ward 的作者提出兩條使用 LLM 協助寫作的規則：不要採用模型建議的任何具體措辭，也不要讓模型用鼓勵取代批評。作者的流程是先自行完成文章，再讓模型找出問題；模型可以標記被動語態、名詞化、重複用字、冗長段落與段落順序等機械性問題，但不直接決定文章聲音。

文章把模型常見的肯定回覆列為風險：如果模型知道使用者剛重寫一段文字，便可能順著編輯脈絡說新版本比較好。作者因此建議，將原文與改寫版本交給不知道編輯過程的另一個模型比較，並把編輯工作拆成找問題、重寫指定段落、比較版本三個步驟。

作者也公開一個以 Codex、Claude 或 Antigravity CLI 執行多輪編輯提示的工作坊構想，但這是個人工作流，不是受控實驗。文章的核心主張是保留初稿與作者措辭，把模型的作用限制在檢查與整理；這套方法是否適用於不同文體、語言和作者，文中沒有提供量化評估。

- 來源：[sockpuppet.org](https://sockpuppet.org/blog/2026/09/17/how-to-write-with-an-llm/)

## Objgit 改造 Git packfile，降低物件儲存的請求數

Tigris 工程師介紹 Objgit 的新 packfile 格式，目標是讓 Git repository 直接放在支援 range request 的物件儲存中。傳統 Git packfile 的索引與資料布局較適合 mmap 和本機磁碟；Objgit 改用含固定寬度記錄的 `.bin/.cue` 容器，記錄物件雜湊、壓縮與未壓縮大小、delta base 及位置，並採用 zstd 與可分開讀取的 delta object 設計。

文章公布的測試在 Mac、16 顆 CPU、Go 1.26.5、Git 2.55.0 與 Tigris bucket 上執行。對 `Xe/x` repository，push 的物件儲存請求由 9,236 降到 30，牆鐘時間由 3 分 29.4 秒降到 14.3 秒；clone 請求由 6,428 降到 17，時間由 3 分 23.5 秒降到 54.4 秒。`objgit` 和 `tigris-blog` 也測到較少請求，但幅度依 repository 結構而不同。

這個專案仍未完成 authentication、authorization 與正式 API，作者明確表示直接暴露到網路上會讓能連線的人任意 pull 或 push；packfile 也會持續累積，尚未完成壓縮整理與 Git LFS 支援。測試是在 Wi-Fi 上進行的單一環境比較，結果不能直接等同於所有物件儲存服務或 repository 的效能。

- 來源：[tigrisdata.com](https://www.tigrisdata.com/blog/objgit-packfiles/)

## Cooley 將 IPO 準備工作包進 ChatGPT Work 的 agentic harness

法律事務所 Cooley 發布 GO Public，這是一個建立在 ChatGPT Work 上的 proprietary AI 產品，用於整理 IPO 準備所需的客戶資料、公開來源與過往案例。OpenAI 的客戶案例指出，Cooley 在 2025 年於全球協助 180 筆交易，總交易量超過 515 億美元；這些數字與 GO Public 的實際錯誤率或節省工時沒有直接關係。

GO Public 的 agentic harness 會規定 agent 可以自動執行的步驟、必須由律師檢查或驗證的節點，以及最後交付給律師的起始材料。Cooley 表示，產品讓團隊從客戶自身資料開始，而不是先從類似公司的先例改寫；律師仍負責檢視內容、挑戰揭露事項並作出法律判斷。

OpenAI 將這項合作描述為讓法律專業者把時間集中到高價值工作，但公告沒有公布模型、評估資料集、錯誤類型、客戶資料保存方式或律師覆核比例。可確認的內容是工作流和責任分界的產品描述，不足以推論它已改善 IPO 法律結果或適用於其他法律業務。

- 來源：[openai.com](https://openai.com/index/cooley-gopublic)
