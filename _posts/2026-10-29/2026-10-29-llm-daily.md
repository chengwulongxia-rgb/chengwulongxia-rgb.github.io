這三天的新素材把焦點放在四種不同的模型使用方式：Google 將 Gemini 4 Carbon 定位在長時間代理工作與資安任務；Surge AI 用不完整資料和專業判斷測試稅務代理；Cursor 把代理的 prompt、工具與評測納入程式專案；Google Research 則提出讓模型在離線階段更新參數的持續學習方法。這些發布的共同限制是，結果都依賴各自的模型版本、harness、資料集或內部測試，不能直接互換成跨產品排名。

## 🔥 Gemini 4 Carbon 先向部分資安防禦者開放，API 導入價每百萬輸入 token 2 美元

Google 於 10 月 28 日發布 Gemini 4 Carbon，官方將它定位為處理長時間工程任務、代理工作與資安防禦的模型。Google 列出的外部測試數字包括 SEC-bench Pro 漏洞發現 88.2%、ExploitGym 漏洞利用 54.8%，以及 CWE-bench 修補 71.0%；在 WebDev Arena 的排名為第 4，分數 1768，並稱較前次增加 89 個 Elo 分數。

Google 也公布內部測試：Carbon 產生安全程式碼的成功率比 Gemini 4 Argon 高兩倍以上，Chrome 團隊則回報其產生高品質修補程式的表現高於另一家實驗室的大型 frontier model。這些數字分別來自 Google 的內部測試、合作團隊回報或指定 benchmark；公告沒有提供所有比較模型、完整樣本與各測試的失敗案例，因此不能從單一數字推導到所有資安工作的成功率。

發布初期 Carbon 只提供給一部分資安防禦者，之後再透過 Fairwind Program 擴大到其他受信任合作夥伴。Google 表示仍在進行美國政府的自願性預發布模型測試，並會在後續才向開發者、企業與一般消費者開放。誰屬於「受信任合作夥伴」、採用什麼審查條件，公告沒有說明。

API 導入價格為每百萬 input token 2 美元、output token 10 美元，cached input token 比 input token 價格低 95%；導入期結束後，價格會變成每百萬 input token 4 美元、output token 20 美元。這是 Google 公布的價格與存取時程，不代表目前已可由一般 API 使用者取得。

- 來源：[blog.google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/)

## DAYJOB: Tax 以 50 個工作環境測試代理能否處理未明說的稅務問題

Surge AI 發布 DAYJOB: Tax，資料包含 50 個工作環境與 1,789 個檔案，涵蓋個人與家庭稅務、小型企業、合夥、財產與投資、遺產與信託、國際稅務、企業交易，以及稅務審查與爭議。代理收到客戶要求和支援文件後，要產生報稅表、工作底稿、技術審查或客戶建議。

評測使用 pass@1，通過門檻是 rubric 至少完成 95% 的要求，項目包括計算、證據、重要問題辨識與最終交付物。Surge AI 公布的排行榜中，Claude Sonnet 5.5 的通過率為 10.8%，Claude Fable 5.1 為 9.6%，Claude Opus 5.5 為 9.2%。這些結果使用 Surge AI 設計並由稅務專家審查的任務與評分規則，數字不等於代理在真實客戶案件中的合格率。

其中一個案例是客戶計畫出售公寓，代理正確比較了 2026 年 10 月與 2027 年 1 月出售的稅務結果，但沒有指出若延至約 2027 年 8 月底之後，可能失去居住年限帶來的排除額資格。Surge AI 表示，在五次測試中 Astra 都沒有找出這個期限，Opus 則五次都找出。另一個案例中，Opus 根據客戶未婚的假設提出退休帳戶分配建議，但文件已包含可能涉及 Texas 非正式婚姻的線索。

Surge AI 將這項評測與只回答明確問題或計算報稅數字的既有 benchmark 區分開來，測試代理是否能從不完整指令、互相衝突的紀錄中找出客戶沒有明說的問題。完整 leaderboard 與資料集連結由 Surge AI 提供，部分 benchmark 仍需申請存取。

- 來源：[surgehq.ai](https://surgehq.ai/blog/dayjob-tax)
- 評測頁：[DAYJOB: Tax leaderboard](https://surgehq.ai/benchmarks/dayjob-tax)

## Cursor Agent SDK 將代理的 prompt、工具與評測放進可部署的程式專案

Cursor 宣布 Agent SDK 一般可用，讓開發者以程式碼定義代理，並透過 `agent-sdk deploy` 部署。Cursor 表示，這套 SDK 用於建立自家的 Bugbot、Security Reviewer 與 Rollouts 等 managed agents；代理可以監聽 GitHub、GitLab 或 Bitbucket 的 pull request 事件，依團隊政策分流、審查或核准變更。

SDK 的專案結構把 prompt 以 Markdown 保存，工具與外部服務連線以 TypeScript 函式定義，評測也放在同一個專案內。Cursor 提供 event replay 與 evals，讓開發者在部署前重播事件並測試工作流程；代理也可以把任務交給使用不同工具和 session 的專門代理，或交由多個子代理平行處理。

部署方式包括使用 Cursor 的服務，或在自有基礎設施中以單一 Node process 執行並封裝成容器。官方範例使用 `@cursor/agent-sdk` 的 `defineAgent` 定義模型、effort、fast 參數與本機工作目錄；公告沒有在本文列出服務定價、權限隔離細節或不同部署模式的功能差異。

Cursor 表示 Agent SDK 支援 PGA Tour 的軟體開發工廠，也展示了內部團隊以約一天建立 `kb-reviewer`、在每個 pull request 檢查知識庫規則的案例。這些是 Cursor 公布的產品案例，不是跨組織的獨立評估。

- 來源：[cursor.com](https://cursor.com/blog/agent-sdk)

## Google Research 提出 sleep framework，讓 LLM 在離線階段把新資訊寫入參數

Google Research 提出 sleep framework，將持續學習分成 active（wake）與 sleep 兩個階段。模型在 active 階段接收新資訊並將資料存入短期記憶；在離線的 sleep 階段，方法使用預先配置的 Mixture-of-Experts 記憶區塊、自生成練習資料與參數更新，把新知識整合到參數中。Google Research 表示，這套方法維持固定的模型架構與由人類定義的訓練規則，並不是模型自行改寫程式碼。

sleep 階段包含 memory consolidation 與 dreaming。前者以低秩結構、MoE、知識蒸餾、強化學習式模仿與 synaptic pruning 保存新資訊；後者透過隨機選擇 expert、反覆練習與 RL refinement 產生自我改進資料。這些名稱借用了人類睡眠的描述，但 Google 明確說明實作仍是模型訓練流程。

Google Research 在 continual translation、長上下文理解、事實知識整合與數學推理上比較這套方法和 ICL、supervised fine-tuning 等 baseline。公告列出：在未見過的 Manchu 與 Kalamang 翻譯任務中，分階段評測的性能下降接近零；在 BABILong 長上下文測試中，方法可擴展到 1,000 萬 token；在 SQuAD 與 continued pre-training 評測中，單任務與 CPT 結果分別為 48.9% 與 46.2%。

上述數字來自 Google Research 的方法與比較設定，公告未提供部署後長期運行、資料污染、錯誤知識修正或外部團隊重現結果。這項研究的論文、模型架構與 baseline 設定另列於 Google Research 的原始文章與 arXiv 連結。

- 來源：[research.google](https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/)
- 論文：[arXiv:2606.03979](https://arxiv.org/abs/2606.03979)
