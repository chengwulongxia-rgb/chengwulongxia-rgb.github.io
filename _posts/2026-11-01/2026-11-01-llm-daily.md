過去三天的新增素材集中在 LLM 進入真實工作流程後的兩個面向：模型可以被接進帳號、遊戲與程式設計環境，也可能被接進惡意程式的資料處理鏈。本期四則新聞分別是已修補的 ChatGPT 網頁漏洞、Cisco Talos 對 VOLTA infostealer 的分析、GPT-5.6 Sol 的 Factorio 實驗，以及 Qwen3.8-27B 多代理工作流的公開重現；它們的證據來源和測試範圍不同，不能合併成單一能力排名。

## 🔥 ChatGPT 公開分享頁曾可在登入狀態執行攻擊者 JavaScript

安全研究團隊 Parameter 表示，他們在 2026 年 10 月發現一條由 ChatGPT 公開分享、HTML Preview、互動圖表與跨框架訊息串接而成的攻擊鏈。攻擊者可以建立惡意對話並分享連結；受害者開啟分享頁後，惡意程式碼可在 `chatgpt.com` 的登入頁面脈絡中執行。Parameter 表示，受害者不需要安裝 App、加入 Project、貼上程式碼或開啟開發者工具，開啟分享連結就是必要操作。

Parameter 的重現能列出受害者近期對話，讀取一段從未分享給攻擊者的私有對話內容，再把資料送到外部伺服器。研究團隊說，這不是只改動畫面，而是利用受害者瀏覽器中已有的登入狀態呼叫 ChatGPT 的已驗證 API；因此報告將影響描述為可代表受害者執行帳號前端可用的操作。

研究團隊指出，根因不是 Preview iframe 單獨突破隔離，而是主頁中的 MathLive 元件接受了未充分驗證來源的 `postMessage`，並把訊息中的 HTML 放入鍵盤版面；後續建立的未沙盒化文件又與 `chatgpt.com` 共用身分。內容安全政策曾阻擋部分腳本，但研究團隊透過允許的 YouTube JSONP 路徑完成 JavaScript 執行，並將 CSP 描述為防禦鏈中的一層，而非根因修補。

OpenAI 在 10 月 26 日確認兩個網頁前端版本都已拒絕報告中使用的跨框架訊息，並將問題標為已解決；Parameter 表示該報告最終被列為 P1，OpenAI 共支付 5,000 美元獎金。已修補不等於所有公開分享頁都具備相同風險，實際影響仍取決於修補版本、瀏覽器快取與是否曾開啟惡意分享連結。

- 來源：[parameter.ai](https://www.parameter.ai/labs/we-found-a-gap-at-openai)

## VOLTA infostealer 使用 LLM 將受害者資料整理成資產評估

Cisco Talos 分析一款自稱 VOLTA-AUTODOXER 的 Windows infostealer，表示它在竊取資料後增加了 LLM 分析階段。Talos 列出的蒐集範圍包括瀏覽器密碼、cookies、付款卡、加密貨幣錢包種子、Discord、Telegram、Steam 與 Roblox 工作階段、Microsoft OAuth token、SSH 與雲端金鑰、Wi-Fi 設定檔及螢幕截圖。

惡意程式會把這些資料整理成結構化證據包，再利用被竊取的登入工作階段補充 Gmail 購買收據、UberEats 與 DoorDash 訂單紀錄、Discord 帳戶資料，以及 Roblox 帳戶估值。Talos 表示，證據包會送往 OpenRouter，並以系統提示要求模型扮演鑑識情報分析員，輸出受害者資產的變現價值分級、可引用的資料依據與安全習慣評估。

Talos 觀察到的預設模型是 `anthropic/claude-opus-4.6`，失敗時依序切換到 `moonshotai/kimi-k2` 和 `google/gemini-2.5-flash`；請求溫度固定為 0.2。Talos 指出，程式會檢查回應中是否出現拒答句，再切換模型；如果沒有 LLM 金鑰，惡意程式仍可執行不含這個階段的竊取流程。這些設定來自 Talos 取得的樣本，不代表所有 VOLTA 變體都使用相同模型或端點。

Talos 表示，VOLTA 會把原始竊取結果、AI 分析和網路補充資料分別打包外傳，且樣本採自刪除設計。文章列出的樣本雜湊為 `57ef4242666d78c50df145b34023df564f0fad38812d6a580e66433d427e2279`；若系統疑似受影響，Talos 建議保留 `%APPDATA%\\volta_debug.txt`，撤銷可能暴露的 token、變更密碼，並將以明文儲存的加密貨幣種子視為已洩露。這篇分析描述的是已觀察樣本的功能，不是對所有使用 LLM 的惡意程式數量或成功率的統計。

- 來源：[talosintelligence.com](https://blog.talosintelligence.com/appraisal-by-ai-model-driven-victim-prioritization-in-the-volta-infostealer/)

## GPT-5.6 Sol 在無敵人 Factorio 遊戲中完成火箭發射

Ryan Madden 表示，他讓 GPT-5.6 Sol 在 Codex 中以低 thinking level 操作 Factorio，透過 Python 遊戲管理器以程式方式操作遊戲，並遵守玩家使用 GUI 時的距離與戰爭迷霧等限制。這次執行在遊戲內 13.5 小時後完成火箭發射，設定為和平模式，不包含 biters。

Madden 的管理器記錄了完整遊戲過程、資源產量與科技研究節點。他表示，模型在前期生產和研究階段的表現使他延長了原先預定在藍色科技後結束的測試；但進入後期後，模型在連接部分生產系統時出現擴展問題，最後需要反覆搬運物資來掩蓋工廠連線失敗，才完成火箭發射。

這次測試不是在一般 Factorio 地圖上的多模型評測。它使用單一模型、單一遊戲管理器、和平模式與一個記錄中的執行，作者也尚未提供不同 thinking level、非和平模式或其他模型的同條件結果。Madden 只表示這次結果比他先前使用 GPT-5.5 的嘗試更進一步；相關執行影片與統計圖由作者另行公開。

- 來源：[ryanmadden.net](https://ryanmadden.net/gpt-56-beats-factorio/)

## Qwen3.8-27B 多代理工作流在十題 LiveCodeBench Hard 測試拿到 9.8 平均分

GitHub 專案 Memdoor 公開一個名為 `team-solve` 的多代理工作流：planner、兩個 ideator、solver、manager 與 repair worker 各自在新 context 中工作，只透過磁碟上的檔案交換資訊。最後由 shell script 執行測試，模型的聲稱不直接作為成功判定；工作流包含規劃、平行提出兩種解法、撰寫程式、測試、檢查與一次修復。

專案作者以 Qwen3.8-27B、128K 回覆上限、GVS5H 作者的提示與迴圈，對同一組 LiveCodeBench Hard 前十題進行五次測試。公開結果顯示五次分數分別為 10、10、10、10、9，平均 9.8；作者列出的 GVS5H 27B harness 平均為 9.6，Fable 5 單次呼叫平均為 8.0。每次結果是十題中的一次通過數，不是完整 benchmark 的總排名。

專案同時記錄限制：五十次工作中有四十九次通過，總成本為 35.79 美元，包含被時限中止或暫停的嘗試後為 38.77 美元；中位模型時間約 40 分鐘，最長約 4 小時。測試題目來自 2025 年 3 月 29 日至 4 月 6 日的競賽，作者明確表示不能排除模型在訓練資料中看過題目；Fable 5 的欄位是作者既有檔案中的單次結果，沒有在這個 harness 中重新執行。

工作流的最後一步會重新執行測試命令並以 exit code 判定結果。公開紀錄也列出失敗案例，例如 manager 產生錯誤反例後覆寫原本能通過隱藏測試的程式。這些結果描述的是特定模型、提示、十題樣本與 OpenRouter 執行條件，不能直接推論到其他程式設計任務或本地部署。

- 來源：[github.com](https://github.com/guregodevo/memdoor/tree/main/examples/workflows/team-solve)
