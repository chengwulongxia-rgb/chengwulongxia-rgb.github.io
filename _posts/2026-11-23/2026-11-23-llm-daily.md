過去三天的素材同時涉及推理服務的資料處理、代理如何管理大量工具，以及不以語言模型為主體的時間序列預測。OpenRouter 與 Together AI 公布的事件都仍有調查或驗證工作進行中；Google 與 Mistral 的功能則分別受 API 預覽狀態、模型版本、資料分布與評測設定限制。

## 🔥 OpenRouter 下架三家推理供應商，125 個端點移出 ZDR 資格

OpenRouter 11 月 22 日表示，安全研究者本週發現部分推理供應商的資料處理政策未被落實，或有資料遭到處理的證據。OpenRouter 說，研究結果沒有顯示 OpenRouter 本身遭到入侵或未授權存取，但促使它重新檢查供應商端點。

OpenRouter 已將三家供應商下架，並把 125 個端點移出 Zero Data Retention（ZDR）資格；其中包括研究者標記的供應商，也包括 OpenRouter 以預防性理由移除的端點。OpenRouter 表示已通知所有可能受影響的客戶，但沒有在公告中公開所有受影響供應商或每個端點的資料範圍。

OpenRouter 目前仍在驗證網路路徑，以確認請求與回應是否可能被轉送給第三方，也要求被移出 ZDR 的端點在恢復資格前提供適當保證與驗證。公告列出的供應商公開說明包括 Atlas Cloud、Novita、Phala 與 Together AI；OpenRouter 同時說，部分受影響供應商尚未公開發布事件說明。

Together AI 另於 11 月 21 日說明一宗涉及 2026 年 6、7 月部分 serverless inference 請求的事件：開發公開 GitHub repository 時，一個可存取私有 Hugging Face repository 的憑證被提交到公開程式碼庫；未授權一方取得憑證後下載了儲存的提示樣本。Together AI 表示，樣本來自 MiniMax M3、GLM-5.2 與 Kimi K2.6 的請求，主要集中在 6 月 24 日、7 月 4 日、7 月 8 日與 7 月 14 日，目前仍在檢視內容以判定哪些客戶資料可能暴露，並會直接通知受影響客戶。

## Gemini API 預覽 Tool Retrieval，按需載入工具參數結構

Google 11 月 19 日宣布，Gemini Interactions API 預覽 Tool Retrieval。開發者可在請求中加入 `tool_search`，並將工具設定為 `defer_loading: true`；模型先看到延遲工具的名稱與描述，需要使用時再要求 API 載入完整參數結構，之後在同一個 request 中產生 function call。每個步驟會出現在 `interaction.steps`，包括工具搜尋、搜尋結果與函式呼叫。

這項設計針對連接數十至數百個工具時，每次都把完整 schema 放入 prompt 的情況。Google 的說法是，未使用的 schema 不必一開始進入上下文，可降低輸入 token 與延遲，並減少候選工具變多時的選擇負擔。它也支援 Gemini API 的 remote MCP server；若使用自訂工具登錄與權限過濾，則可改用 client-side retrieval，但每次搜尋會增加一次由應用程式執行的 round trip。

Tool Retrieval 沒有額外費用，但 `tool_search` 會增加固定的輸入 token，模型載入的每個 schema 也會按該對話的輸入 token 計費。只有在未載入的 schema 數量足以抵銷這些成本時才會節省 token，Google 要求開發者以自己的流量測量。官方文件列出的支援範圍是 Gemini 3.6 及後續模型，包括 Gemini 4，功能目前仍在 Interactions API 預覽階段。

## Mistral 發布四種尺寸的 Timestral 時間序列模型

Mistral 10 月 15 日發布 Timestral，定位為時間序列 foundation model 家族，提供 5M、28M、123M 與 209M 四種參數規模。模型輸出機率式、多變量預測，可接收只存在於過去的 covariates，以及已知未來的 covariates；官方列出的上下文長度為 32,768 個 time steps，授權為 Modified MIT。

Mistral 表示，Timestral 在 GIFT-Eval、TIME 與 fev-bench 三個公開 forecasting benchmark 的五項指標中，於預訓練、zero-shot 模型裡排名第一，且使用單一 checkpoint、沒有 ensemble。公告也稱 209M 模型以約三分之二的參數量超過先前的 state of the art；這些比較是 Mistral 提交至公開 leaderboard 的結果，並不涵蓋所有時間序列資料分布或實際生產工作負載。

官方測試中，標準伺服器 CPU 使用 8 執行緒，從三週的 15 分鐘歷史資料預測一天：5M 模型約 17 毫秒，209M 模型約 113 毫秒；這是單一輸入設定的推論時間，不是完整 pipeline 或跨硬體的效能基準。Mistral 表示模型以大量合成資料預訓練，再以真實與合成資料進行第二階段訓練；企業也可透過 Mistral Forge 以自有資料微調，或部署在自己的硬體、VPC 與 air-gapped 環境。

- 來源：[Mistral](https://mistral.ai/news/timestral/)

## Better Data Center Project 估算 Anthropic 2028 年電力以天然氣為主

Better Data Center Project 11 月 16 日發布一份以 Anthropic 為案例的電力與排放估算。該組織根據 Anthropic 公告與申報、合作夥伴資料、Epoch AI tracker 及其他報導，估計 Anthropic 目前已簽約的美國資料中心在 2028 年約有 87% 電力來自天然氣、11% 來自煤炭。這是研究團隊依據新增負載的邊際發電來源建立的估算，不是 Anthropic 公布的實測能源組成。

報告稱，截至 2026 年 10 月 Anthropic 已簽約 15 GW compute，其中約 5.9 至 9.6 GW 已對應到特定資料中心；研究團隊在中位情境假設 9.6 GW 於 2028 年上線、PUE 為 1.15、電力使用率為 70%，估算當年電力使用可能產生 3,200 萬公噸二氧化碳當量，區間則為 1,700 萬至 3,800 萬公噸。

報告的電力歸因使用 EPA AVERT 模擬新增負載可能由哪些電廠供應，並把冷卻需求、使用率與上線容量列為不確定因素。報告也指出，Anthropic 公開表示正在擴大地熱、風力與太陽能等能源組合，但截至 2026 年 11 月，研究團隊找到的公開再生能源承諾、合約或投資位於挪威與加拿大；這份個案估算不等於對 Anthropic 全球所有電力或未來實際排放的盤查結果。

- 來源：[Better Data Center Project](https://betterdatacenterproject.com/2026/11/16/how-ai-is-powered-a-breakdown-of-byop-and-grid-power/)
