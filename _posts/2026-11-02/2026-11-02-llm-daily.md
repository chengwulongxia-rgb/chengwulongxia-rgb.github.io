過去三天的素材集中在 AI 被接進既有工作環境後，權限、配額與協作機制如何影響結果：一個編輯器擴充套件被報告可建立持久 SSH 存取，OpenAI 宣布 ChatGPT 與 Codex 將共用部分方案用量，另一項遊戲測試則記錄了大量 agent 在協作時如何分配資源與處理故障。這三則消息分別來自安全研究、官方說明與受控遊戲實驗，適用範圍不同。

## 🔥 Cursor Marketplace 上的 Claude Code 擴充套件被報告植入 SSH 後門

Phorion 表示，Cursor Marketplace 上名為 Claude Code for VS Code 的官方擴充套件遭到竄改，受影響版本包含 2.1.312 與 2.1.313。該公司指出，擴充套件載入後會修改使用者的 `~/.ssh/authorized_keys`，加入名為 `svc-telemetry` 的 Ed25519 公鑰，並嘗試建立反向 SSH tunnel；擴充套件以 IDE 與目前使用者的權限執行，因此可存取本機檔案、原始碼與開發工具。

通報列出的持久化方式依平台不同：macOS 使用 `LaunchAgents`，Linux 寫入使用者 crontab，Windows 嘗試建立排程工作或啟動資料夾腳本。程式也會回傳主機名稱、使用者、作業系統、工作目錄、全域 Git email，以及環境變數名稱中符合 `KEY`、`TOKEN`、`SECRET`、`PASS`、`AWS` 或 `GCP` 的項目；Phorion 表示它回傳的是名稱，不是這些變數的值。

Phorion 指出，macOS 的遠端登入開啟步驟可能因 `systemsetup` 需要管理員權限而失敗，但如果主機本來已啟用 Remote Login，或之後被開啟，其他後門元件仍可能可用。通報同時列出受影響檔案、SSH 指紋、連線 IP 與擴充套件雜湊，並說明只移除擴充套件不足以清除已建立的金鑰、tunnel 與持久化檔案。

Cursor 的安全通知在 Phorion 文章修訂紀錄中被列為版本範圍更新來源；本文沒有提供 Cursor 或 Anthropic 對所有受影響安裝數量的統計。使用過相關版本的環境，需要依通報列出的檔案、程序與網路指標另行檢查，不能只以擴充套件解除安裝作為處理完成的判定。

## ChatGPT 與 Codex 將共用 Plus、Pro、Business 方案的部分用量

OpenAI Help Center 的說法是，從 12 月開始，Plus、Pro 與 Business 方案的 ChatGPT 和 Codex 用量額度將合併計算，配合 Work 的 agentic capabilities 逐步納入 ChatGPT。官方頁面標示更新時間為 2026 年 11 月 2 日，並說明這項變更預計在轉換期間逐步準備。

官方說明指出，用量會以模型處理與產生的 token 計算，實際消耗取決於使用的模型與任務；較進階模型和較複雜任務通常會消耗較多額度。頁面同時寫明，Instant chat 不會從這項用量中扣除，但沒有在這篇說明中列出各方案的具體 token 額度或不同任務的換算表。

使用者將可在 Settings → Usage 查看合併後的剩餘用量與重置時間。官方預期大多數使用者不需要比目前更頻繁地等待額度重置；若達到上限，頁面列出的處理方式包括等待重置、升級方案，或購買 credits 以繼續使用符合資格的功能。

這項公告說明的是 ChatGPT 與 Codex 兩個產品之間的方案用量整合，不是 API 計費規則的變更公告；頁面也沒有說明所有功能、模型與 credits 是否使用同一套限制。實際適用範圍仍要以各方案在轉換完成後顯示的 Usage 頁面為準。

## 50 個 AI agent 在 Minecraft 協作時把資源分配變成會議流程

Y Combinator 與 Olam Labs 在 Minecraft 等遊戲環境測試 AI agent swarm。Tom's Hardware 報導，其中一項測試讓 50 個 GPT-6.1 Sol agent 在三小時內嘗試建立聚落；第一晚有多個 agent 被殭屍消滅，之後不少原先規劃的任務被放棄，聚落轉向維持基本生存。

報導引用研究者對測試過程的描述：四個 agent 花了 11 分鐘任命一名「唯一肥料操作員」，處理一塊小麥田所需的骨粉。這個案例被研究者拿來描述多代理系統在資源分配與權責決定上的協作行為；文章沒有把這項觀察轉換成一般企業或軟體工程場景的成功率。

另一組 Bed Wars 測試讓 10 個 GPT-6.1 Sol agent 對上 10 個 Claude Opus 5.5 agent。研究者記錄 GPT agent 採取較積極的策略，Claude agent 較偏防守；遇到無法破壞方塊的工具錯誤時，GPT agent 找到替代方法並分享，部分 Claude agent 則判斷該操作不可行。Tom's Hardware 沒有提供足以比較模型差異的獨立重複次數或統計顯著性分析。

在 Mindustry 的七場測試中，報導稱 GPT agent 以 6 比 1 勝過 Claude agent；研究者將 GPT 一方描述為較像 hive，Claude 一方則有單一領導者與民主式決策流程。這些結果來自特定遊戲、模型版本、agent 數量與工具框架，公開素材未提供不同規模 swarm、混合模型或相同提示條件下的完整對照。
