## 🔥 GLM-5.4 以權重共享迴圈增加模型深度

Z.ai 11 月 23 日發布 GLM-5.4，稱這是第一個採用 Loop Transformer 的 GLM 模型。標準 Transformer 的每層在一次 forward pass 中執行一次；Loop Transformer 則讓一組共享權重的層重複處理前一輪的 hidden states，在不按相同比例增加參數量的情況下增加計算深度。Z.ai 表示，這次做法不是從零訓練迴圈模型，而是把已預訓練的 GLM-5 base model 繼續訓練成迴圈架構，以避開相同預訓練計算量下權重共享模型可能落後的問題。

官方技術說明指出，GLM-5.4 在 750B 規模上讓 GLM-5 的 28 層迴圈執行兩次，並搭配 gated progressive updates 等架構調整。公告把軟體工程、資安、3D 建模與實體控制列為超長鏈推理任務，但沒有在這篇文章中提供足以獨立重現的完整訓練設定或跨模型評測表。Z.ai 也承認模型會陷入過長的「marathon thinking」迴圈，並稱這種持續反思與自我修正通常能提高準確率；這仍是發布方對模型行為的描述。

GLM-5.4 可透過 Z.ai Chat、ZCode 與 Coding Plan 使用；API 在公告中標示為 coming soon，模型權重則列在 Getting Started 的 Open Weights 項下，但該頁面擷取內容沒有提供完整下載與授權細節。Z.ai 表示後續會研究讓較難的 token 動態取得更多迴圈次數，這不是目前已公布的功能。

## Shirudo 以 eBPF 在 Linux 修補前套用暫時防護

OpenAI 與 Cisco 11 月 23 日發布開源 Linux runtime Shirudo，用於在永久修補程式準備與部署期間，對仍在運行的系統套用暫時性 shield。Shirudo 使用 eBPF，在作業系統指定位置觀察活動並套用針對性的保護；營運者可以先測試 shield 對正常請求的影響，再決定是否啟用。官方說法是，這能處理某些惡意利用與合法請求依賴相同 Linux 操作、無法直接封鎖整個操作的情境。

OpenAI 公布的功能設計包括不重啟即時防護、由代理協助調查漏洞與產生 shield、簽章驗證，以及透過 Linux eBPF verifier 和核心安全控制限制未授權修改。Shirudo 也使用 Trusted Platform Module（TPM）支援記錄防護載入或移除的可驗證證據。這些是專案的設計能力；公告沒有把它們描述成已涵蓋所有核心、工作負載或攻擊方式的保證。

在一項由 OpenAI 連結的 controlled test 中，Codex 產生的 shield 被用來阻擋針對運行中 Elasticsearch 服務的 Java4Shell exploit 嘗試，測試結果稱不需要重啟且服務仍可運作。這是單一漏洞與服務情境的測試，不等於對其他漏洞的防護效果。Shirudo 以 BSD 2-Clause 授權開源，BPF 程式採 BSD 與 GPL 雙授權；實際部署仍需由安全團隊簽署、載入並驗證 shield。

- 來源：[OpenAI](https://openai.com/index/introducing-shirudo)

## Claude Ship 將 Pull Request 修正與核准納入自動流程

Anthropic 11 月 23 日宣布 Claude Ship beta，讓 Claude Code 相關代理在 GitHub Pull Request 上執行程式碼審查、提出或套用修正，並依團隊設定的政策判斷是否達到核准條件。產品由已正式推出的 Code Review，以及 beta 的 PR Steward 和 Claude Approvals 組成。管理者可以按 repository 啟用、設定 review level、執行頻率與每月花費上限，也能先以 observe mode 執行核准政策。

Anthropic 表示，Claude Ship 可讓團隊決定哪些變更仍需人工處理；官方文章也明確提醒，Claude 可能漏掉 bug、安全漏洞或其他問題。產品案例與客戶引述是 Anthropic 公布的採用經驗，不是獨立的缺陷率或安全性評估。

目前 Claude Ship 只提供給 Claude Team 與 Enterprise 方案、且 repository 必須位於 GitHub。Code Review 已一般可用，PR Steward 與 Claude Approvals 仍是 beta。使用量按 token 計費，成本會受 Pull Request 數量與大小、審查層級、執行頻率及 PR Steward 工作量影響；政策中的 classifiers 也會計費。Claude Ship 不提供給採用 Zero Data Retention、HIPAA configuration 或 customer-managed encryption keys 的組織。

- 來源：[Claude](https://claude.com/resources/articles/introducing-claude-ship)

## 研究以 KV cache 實驗測試模型是否能偵測概念注入

ACS Research 與 Charles University 的研究者在 arXiv 發表論文，使用 Qwen2.5-Coder-32B-Instruct 測試模型能否偵測先前對 KV cache 施加的概念注入。實驗先在模型處理第一輪訊息時，對第 21 至 42 層加入概念 steering vector，再移除 steering，接著詢問模型是否察覺注入，藉此排除模型直接看到持續中的擾動或從自身輸出猜測的部分解釋。研究也用 control questions 與 norm-matched Gaussian noise 比較，以區分概念特定訊號和一般 activation perturbation。

在沒有額外文件的條件下，模型對注入的「是」回答敏感度只有約 0.3%；加入特定提示後，研究者報告敏感度可升至 39.9%，false positive 只增加 0.6%。在九個概念的識別實驗中，研究報告最高可取得 1.66 bits mutual information；例如 programming 的識別率為 99.9%、truth 為 86%，但 cats 與 bread 沒有被辨識。這些數值來自特定模型、概念集合、提示條件與 logit 分析，不是模型在一般對話中可靠自我報告的準確率。

研究者在 Llama-3.3-70B-Instruct 與 Qwen2.5-72B-Instruct 做有限複製，觀察到相似訊號，但不同模型對提示條件的反應差異很大。論文也明確區分「表示中存在可讀出的注入資訊」與「模型已建立二階元認知監控」；目前證據支持前者的部分實驗結果，不能直接證明後者。研究使用的是公開開放權重 checkpoint，並公開重現程式碼；作者列出的主要實驗約使用 75 GPU-hours，完整專案約 600 GPU-hours。

- 來源：[arXiv](https://arxiv.org/abs/2602.20031)

## SkillPrivus 靜態審查技能在正常用途下的隱私風險

Mariana Fernandez-Espinosa等四名研究者於11月19日提交SkillPrivus論文，檢視技能即使沒有惡意、照功能說明工作，是否仍讀取、推導、保留或傳送超出任務需要的資料。系統不執行技能，而以gpt-oss-120b從指令與程式抽取資料操作、原碼證據及接收方，再依功能宣告與資料領域規範判定潛在用途偏離。

研究蒐集726個技能，排除118個未辨識到個人資料處理的技能與45個分析未完成案例後，在563個完成分析的技能中標記307個至少有一項潛在問題，比例54.5%。22,158項資料操作中有2,144項被標記；這些是靜態審查結果，不是已發生外洩、惡意技能比例或整個市場的風險估計。

作者以21個技能的311項去重操作請三名STEM博士生判讀，模型與人工在可判定操作上的平均一致率為83.2%、Cohen’s κ為0.346；受試者看得到系統已抽取的資料流與來源證據，因此不等於驗證抽取沒有遺漏。作者也明說，將特定敏感資料預設留在本機、除非明確要求先取得同意，是審查政策選擇，不是GDPR一律要求本機處理的法律規定。

在NVIDIA樣本中，兩個後端都完成分析的37個技能，gpt-oss-120b標記24個、GPT-5標記18個；兩者抽取的操作數分別是2,232與2,743，未逐項對齊。這項比較不能直接當成安全掃描器漏報率，也不能把數量排名相關解讀成抽到了相同內容。Privacy Card提供的是可追溯的審查摘要，論文未驗證其建議能否降低實際傷害。
