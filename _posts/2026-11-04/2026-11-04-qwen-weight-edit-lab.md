一個小模型答不出數學題，可能是算錯，也可能是反覆檢查到輸出額度用完，根本沒交出答案。這兩種失敗若只算成「答錯」，就很容易把改善的方法也看錯：它需要更長的生成額度，還是需要修正讓它卡住的行為？

這次實作拿作者已公開的 **Qwen 權重補丁**，測三件能直接回答的事：照著套回模型是否有效、只給原模型更多生成空間是否也能改善，以及換成相近幅度的隨機修改是否有相同表現。沒有重新訓練模型，也沒有呼叫Astra幫忙作答或重新發明補丁。

先講收穫：在固定16題中，長額度下原模型答對0題，作者補丁版11題，指定隨機版2題；作者版若只給短額度，也僅答對2題。**這個補丁值得研究的地方，是讓模型較能在有限額度內完成並答對；但它不是一個讓小模型立刻用短回答解決問題的捷徑。** 下文依序交代這三個比較為何需要、如何執行，以及結果能拿來做什麼。

## 原文摘要

Rikiya Takehi等人在2026年11月2日發表Weight-Space Programming，測試語言模型辨認與修改神經網路權重。其中Qwen3.5-0.8B的實驗，讓Astra使用Python、練習資料與前向測試回饋，尋找不經梯度下降的權重修改。作者報告，在其完整MATH-500評測中，分數由7.9%升至48.1%，並將主要收益連到反覆生成的修復。[1][3]

Matthew Honnibal的批評是：小網路的「只看原始數字、沒有工具」，與Qwen的「使用Python、觀察測試回饋再修改」，不是相同條件。後者成功，不能直接當成前者已擴展到大型模型的證據。這個爭論談的是能力宣稱與證據能否對應，不是宣告權重補丁沒有工程價值。[2]

本篇不重做Astra尋找補丁的過程。我們只下載它最後交付的公開差分，重建修改版Qwen，再用自己的固定小樣本測它的效果。原作者也已公開Gemma 3 270M改善有限的後續案例；不能因一個模型的病態行為被改善，就外推成任何模型都能同樣受益。[6]

## 一、我們到底拿什麼來測？

把這次實驗想成測試一份「模型修補檔」，而不是再造一個AI。

先固定一份Qwen3.5-0.8B。它收到題目後，會先產生思考文字，再產生答案。我們不改題目、不加解題提示，也不把參考答案交給它。唯一主要介入，是替換作者指定的部分權重。測試用題目來自MATH-500：在推論前將500題按固定seed打亂，取前16題，三組模型回答完全相同的題目。[5]

接著準備三組：

- **原版**：不改權重。它告訴我們，這個模型原本能做到什麼。
- **作者補丁版**：套用公開的最終差分。它回答「這份修補檔照著用，有沒有效」。
- **隨機對照版**：在同一批欄位，以相近幅度改動，但打亂差值的方向。它用來檢查，改善是否連這個不照作者方向修改的版本也做得到。

每組再各給8,192與32,768個生成token的上限。token是模型生成文字的計量單位，不是秒數；長額度允許它繼續寫，不會直接告訴它正確答案。

因此，這裡是16題、每題六個條件、每條件一次生成，共96筆輸出，**不是96道不同的題目，也不是完整MATH-500重跑**。思考模式、題目、temperature等取樣設定固定；seed按題配對。原作者完整評測每題有四次生成，不能拿我們的11/16去宣稱重現其48.1%。[3]

## 二、為什麼不能只測「原版對補丁版」？

因為即使補丁版分數上升，也還有兩個不同的解釋需要比較。

**第一個是預算：是不是模型根本沒壞，只是我們太早把它截斷？** 如果如此，讓原版多寫一些，也應該能救回部分答案。所以我們沒有只報作者版的長額度分數，而是讓原版也跑同樣的兩個上限。

**第二個是改動方向：是不是只要動這些權重，就可能把模型從原本的路徑推開？** 所以加入隨機對照，而不是把所有改善都直接記在作者的修改策略名下。

隨機對照並不是任意撒雜訊。我們先取得作者差分相對原版的變化，在每個被修改欄位內，置換差值的列位置，再加回原權重。這保留捨入前的每欄範數，也就是修改幅度的衡量方式，但不保留原來的向量方向。轉成BF16後實際範數會稍有差異，紀錄另保存捨入誤差與雜湊。

這只是一個事先固定的隨機seed。它能作為一個具體反例對照，不能代表所有隨機修改的分布，也不能證明作者找到唯一有效方向。

## 三、結果一：只給原版更多生成空間，沒有救回這16題

先看最直接的問題：不套補丁，只延長額度，行不行？

- 原版、8,192上限：答對 **0/16**，16題全部被長度上限截斷。
- 原版、32,768上限：答對仍是 **0/16**，16題仍全部被截斷。

這不是說Qwen永遠不會數學，也不是說增加生成額度永遠無效。它回答的是很具體的事：**對這個固定模型、這16題與這套取樣設定，單純把上限拉長，沒有得到更多正確答案。**

因此，這次作者版的提升不能只用「它得到更多tokens」解釋，因為原版也拿到了相同的長額度。

不過，碰到上限只證明被截斷，不能把這16題全部自動貼上「迴圈」標籤。我們另外讀原始輸出，才能確認下面案例確實存在反覆檢查；全體的長度統計與文字診斷仍分開保存。

## 四、結果二：補丁有效，但多數答對發生在短額度之後

每一列的分母都是同樣16題、每題一次作答。「答對」以最後完整boxed答案比對參考答案；「結束思考」則只看有沒有輸出思考結束標記，兩者不是同一件事，不能相加。

### 8,192-token上限

- 原版：答對 **0/16**；結束思考0/16。
- 作者補丁版：答對 **2/16**；結束思考2/16。
- 隨機對照版：答對 **1/16**；結束思考1/16。

### 32,768-token上限

- 原版：答對 **0/16**；結束思考0/16。
- 作者補丁版：答對 **11/16**；結束思考13/16。
- 隨機對照版：答對 **2/16**；結束思考2/16。

![同樣16題的三組權重與兩種生成上限比較]({{ '/assets/images/2026-11-04/qwen-weight-edit-lab-results.png' | relative_url }})

灰色是短上限，藍色是長上限；每根計數柱的分母是16題。最下圖是平均輸出token數，不是GPU秒數或費用。圖直接來自保存的96筆輸出，沒有重新呼叫模型。

這裡有兩個不同的收穫。

第一，作者補丁版長額度答對11題，指定隨機版只有2題。**在這個指定對照中，並不是改了相近幅度就有相同表現。** 但一個隨機seed與小樣本，還不足以推論作者方向普遍優於所有隨機修改。

第二，作者版不是一改就能在短額度裡完成。它從短額度的2題變成長額度的11題。我們事後逐token核對，作者版16個長短配對的共享前綴完全相同；新增答對的9題，確實是在原本8,192上限之後才交出最後正確答案，並非換抽了一套早期回答。沒有原先答對、延長後反而答錯的題。

所以，這次測到的不是「補丁」或「額度」二選一：**作者補丁與足夠的生成額度配合，才得到這批題目中的主要收益；原版單獨延長沒有相同結果。**

隨機對照的長額度是在另一部VM補跑。其權重雜湊、軟體版本、題目與seed雖相同，長短配對卻只有1/16具有相同共享前綴，原因未定位。因此不能把隨機版的1題到2題，也解讀成同一批早期軌跡單純延長；它只是兩個條件下各自觀察到的成績。

## 五、看一個實際案例，就知道「改善」長什麼樣

第一題問地圖比例：圖上3英吋代表實際10英里，實際相距53.25英里的兩棟建築，在圖上是多少英吋，答案以分數表示？這是題目的中文轉述；模型收到的是資料集原英文與固定作答指令，完整prompt在公開JSONL中。

參考答案是 `639/40`。原版寫滿32,768 tokens後被截斷；尾端仍反覆懷疑題目措辭，甚至把同一句話當成可能的筆誤。作者版最後以正常stop結束，給出：

```text
\boxed{\frac{639}{40}}
```

但作者版也用了 **30,200 tokens**。在思考結束後的回答裡，「Wait, I need to check the reasoning again.」仍出現22次。

這不是「改完就變成簡潔的數學老師」。更接近這樣的工程改善：原本一直兜圈、在額度內交不出答案的生成過程，修改後比較有機會走到結束並答對；但大量無效檢查仍可能存在。

這題是事後依固定題序，挑第一個「原版錯、作者版對，而且作者版結束思考」的配對作解說，不能代表全體。它的作用是讓前面的分數有具體形狀：**答對率變好，不必然表示每一步推理都更乾淨。**

長額度下，作者版平均輸出19,057.5 tokens，原版則每題都寫滿32,768。這也說明，在這組測試中，較多正確答案並不是靠平均寫出更多字換來的。但這是token數比較，不是同等比例的費用節省或執行時間保證。

## 六、這份補丁改的是什麼，而不是什麼？

它不是把答案表塞進模型，也不是在prompt後面加「不要一直想」。推論時沒有Astra在旁邊修正答案。修改發生在模型內部的兩個MLP輸出矩陣：第15與第19層，各選64欄。[3]

可以把這些欄位理解成「中間神經元把訊號寫回模型的方向」：神經元產生一個活化值，乘上對應欄向量，再與其他神經元的貢獻加總。因此，改一欄不是直接指定某個詞，而是改它往後續計算送出的訊號。

作者的方法說明是，先比較有產出的上下文與反覆生成的上下文，找出與反覆相關的方向，再削減最強烈寫入這個方向的部分欄位。這是作者尋找補丁時的診斷與設計意圖；**本篇沒有重新測量那些內部方向，只重播最後留下的修改。**[3]

我們做的是把公開差分重建成BF16權重。核心程式如下：

```python
bits = base.contiguous().view(torch.uint16).numpy().copy()
assert sha_bytes(bits.tobytes()) == t['base_sha256']
edited = sparse_rebuild(bits, z[f't{i}_idx'], z[f't{i}_val'])
assert sha_bytes(edited.tobytes()) == t['edited_sha256']
```

第一個雜湊確認拿到同一份原始張量；中間一行替換指定位置；最後一個雜湊確認修改後的位元組與作者公開檔案相符。這些檢查的用途，是排除「其實套錯補丁」這個解釋。

兩個矩陣各為 `1024 × 3584`。選中位置共131,072個，其中實際BF16值不同的有130,188個；有些操作最後捨入回原值。完整位置、前後數值、範數與SHA-256留在程式庫，不必靠讀者從幾個浮點數猜測模型行為。[3][7]

## 七、測完之後，實際可以拿這個結果做什麼？

### 先分清「算錯」與「出不來」，再決定怎麼改

這次原版兩種額度都是零分，單看正確率，會把它與能正常作答、但答案全錯的模型放在一起。加入結束行為後，才看得出前者16題都寫到上限；再讀原文案例，能定位其中反覆檢查的失敗。

對這份模型而言，這會改變下一步：不是立刻再把生成上限往上加，而是先處理生成過程為什麼不結束。若換成一個能正常結束、卻總是算錯的模型，本篇就沒有證據說這份補丁仍是對的處方。原作者在較少反覆的Gemma 3 270M上，格式寬鬆分數僅由6.8%到7.0%，也提醒我們不要把這個修補當成通用能力升級。[6]

### 評估補丁時，連同可用的生成額度一起決定

如果應用只允許8,192 tokens，就不能拿作者版在32,768上限的11/16當成部署成績；在短額度下，它實際只有2/16。反過來，只測短額度又會漏掉這份補丁在更長生成中的收益。

因此，可重用的做法是把「權重版本 × 生成上限」一起列成測試條件，再同時看答對、截斷與輸出量。這不是所有模型都應多想的建議，而是避免拿另一個資源設定的跑分替目前應用背書。

### 保留真正驗到的工程價值，不替它追加沒測過的能力

本篇成功驗到的是：公開補丁可以重建，在指定16題與取樣條件下改善完成與答對表現，而且指定隨機對照沒有相同成績。這足以支持繼續研究這個特定方向。

但「新增數學能力」與「原有解題過程比較能完成」，沒有被這個設計充分拆成獨立原因。我們也沒有讓Astra只看權重、重新找補丁，所以不能用這96筆替那項能力作證。進一步的能力歸因，需要另外設計能分辨這些原因的測試。

## 八、怎麼自己核對，而不是再花一次GPU費用？

[主要原生Notebook](https://github.com/chengwulongxia-rgb/deep-dive-code/blob/7985ff3476001e03428937193ee8d453648c9021/weight-space-programming-lab/weight_edit_colab.ipynb)預設是CPU重播：讀保存的模型原始輸出，重新評分與畫圖，不下載模型、不使用GPU，也不需要HF token。資料、權重重建、推論與評分程式都在原生cells中，不是把核心藏在外部腳本。[7]

```bash
git clone https://github.com/chengwulongxia-rgb/deep-dive-code.git
cd deep-dive-code/weight-space-programming-lab
uv sync --frozen --extra notebook --python 3.13
uv run python -B -m unittest test_notebook -v
uv run python verify_replay.py
```

本次用Colab L4、BF16與固定模型／資料revision；vLLM0.25.0、Transformers5.17.0、Torch2.11.0+cu129、math-verify0.9.0。評分取最後完整boxed答案，沒有box即錯；思考段內的box仍可能算對，所以思考結束另列，截斷與重複診斷不當成迴圈真值。Qwen模型卡本身已有小模型思考模式可能反覆生成的警訊。[4]

96筆來自中斷輪的80筆加補跑16筆，不是單次GPU Run all。原始檔、來源輪次、固定選題、版本與停止紀錄都保留；CPU重評零錯誤診斷，11項測試與乾淨kernel的10個code cells重播均通過。全部安裝、失敗與執行累計185.51分鐘，VM均已停止。

若要新跑模型，才將`RUN_GPU`改為`True`，另設已授權L4、HF憑證與主機硬截止；Notebook不自行申請或停止付費VM，歷史同意也不是新執行授權。

## 城武觀點

正確率可以記成果，不能單獨開處方。這次最值得保留的，不是把11題改寫成一個能力口號，而是原版拿到更多生成空間仍沒有救回這16題，作者補丁卻在長額度下改變了結果。對實作者，這意味著先辨認模型是在算錯，還是在交卷之前就耗盡預算；兩種失敗不能共用一個處方。原作者願意公開差分，讓外部能把這個效果拿出來驗，這是價值所在。至於Astra如何找到它、是否理解權重，仍要由對應的測試回答。把可重播的修補效果和模型理解分開，不是貶低工程進展，而是不讓一個總分替所有因果問題作答。

*城武的未解檔案——先弄清楚模型是算錯，還是根本交不出答案，再決定下一筆算力要花在哪裡。*
