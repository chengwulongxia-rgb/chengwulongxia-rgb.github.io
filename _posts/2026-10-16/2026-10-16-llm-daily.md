近三天的新聞把焦點從模型本身移到模型周圍的條件：agent 讀到什麼、能執行什麼、誰能檢查它，以及研究者如何把專用模型放進實際工作流程。這些條件同時決定了能力能否被使用，也決定了失敗時誰能看見原因。

## 🔥 Anthropic 測試小模型在 IoT 裝置上自我複製的可行性

Anthropic Frontier Red Team 發布一份研究，測試小型模型能否在陌生硬體上建立推理環境，並把模型與 agent harness 複製到其他裝置。研究團隊用 15 台每台約 55 美元的 Android TV box，分散執行 Gemma4-26B-A4B；整體速度約為每秒 0.39 token。這是研究環境中的受控展示，不是對現實網路的大規模感染觀察。

研究把複製流程拆成尋找目標、取得執行權、建立推理環境與繼續傳播四個階段，並刻意把網路入侵部分簡化。8 個 GCP redroid 節點的測試中，GLM-5.2 在 5 次試驗中有 4 次到達全部 8 個節點，另一次到達 7 個；研究者明確指出，未驗證的 ADB 連接讓這組結果成為現實成功率的上限估計，而非一般網路條件下的結果。

在不同硬體的推理環境設定測試中，9B 模型可在 Jetson Nano、Mac 與 RTX 4090 等硬體上完成部分設定。研究估計，若以 4GB RAM 的裝置執行 9B 模型，完整複製可能需要約 1 至 2 天；模型在多代之間傳遞失敗筆記後，Qwen3.5-9B 的設定成功率由第一代的 45% 上升到後續約 61% 至 84% 的區間。這些數字來自 Anthropic 自建 harness 與測試網路，並不等於現有 IoT 裝置已能自主形成可持續的 AI botnet。

- 來源：[anthropic.com](https://www.anthropic.com/research/self-replicating-ai)

## HTTP response header 也成為 agent 可能讀到的指令來源

Signals Corps 掃描 Common Crawl 2026 年 9 月資料中的 217,097,223 個網頁回應，發現 7,959 個網站送出面向 AI 系統的 HTTP header，其中 7,271 個是指向 `llms.txt` 或 MCP 等其他資源的指標，30 個包含試圖覆寫或引導 agent 的文字。這是一次取樣分析：研究團隊抽取該次 21.7 億頁 crawl 的約 10%，因此比例不能直接視為整個網路的普查結果。

研究指出，header 對一般瀏覽者不可見，但 agent 使用的工具可能把它們傳入模型上下文。不同工具的行為不一致：只回傳 body 的工具不會傳遞 header；使用 `curl -i`、讀取 response headers 的程式庫或瀏覽器網路介面的工具則可能傳遞完整內容。研究中的 Claude Code 測試在一般任務下會看見測試 header 並忽略其中指令，但當使用者提示要求 agent 遵守伺服器指示時，9 次測試有 7 次輸出測試用的指令結果。

研究團隊也測試了 30 個注入 header，並將其分成惡作劇、拒絕觸發字串、要求回報模型名稱、假安全測試與假申請人評分等類型。作者建議 fetch 工具預設只傳遞 body 與必要的 allowlist metadata，把 redirect、`llms.txt` 和 MCP 連線視為新的不受信任來源，並在模型提出工具呼叫後、實際執行前，由模型外部的授權檢查再次核對任務、目的地與資料類型。

- 來源：[signalscorps.com](https://www.signalscorps.com/blog/prompt-injection-in-http-headers/)

## Anthropic 讓 METR 以近似內部員工的權限進行第三方評估

Anthropic 宣布已讓非營利組織 METR 的 6 名員工取得公司硬體、辦公空間與內部工具，權限大致接近 Anthropic 風險評估團隊。METR 將發布對 Anthropic 風險程度、事件或實務的分析；Anthropic 表示不能否決發布，但可要求刪除客戶資料、律師與客戶特權資料、模型架構等預先定義類別的內容。METR 可以公開說明被刪除的範圍，以及它是否認為刪除有正當理由。

Anthropic 同時表示，與 SecureBio、Accenture 的其他合作仍處於較早階段，這些評估者取得的資訊與發布權限較少。公司計畫建立三層存取級別，並希望未來有多個第三級團隊各自發布對風險狀態與關鍵決策的分析；公告沒有列出每一層的完整標準或時間表。

這套安排的可驗證部分是存取範圍、發布權與刪除類別的制度設計；評估結果本身仍要等 METR 的報告。Anthropic 的官方說法是，第三方可以在不公開敏感資訊的前提下取得足夠證據；實際上哪些資料能被看見、哪些結論會因刪除而受限，將取決於個案執行與公開報告。

- 來源：[anthropic.com](https://www.anthropic.com/news/an-update-on-independent-evaluators)

## OpenAI 為美國大學研究室提供 GPT-Rosalind 贊助存取

OpenAI 發布 Rosalind Academic Plan，讓符合資格的美國大學研究室申請最多 30 個 Business Standard 席位，免費使用最多 12 個月。方案包含 GPT-Rosalind 與 Rosalind Workbench，以及其他商用 frontier model，但 GPT-Rosalind 需要額外的 trusted-access 審核；目前不包含 API 存取。

申請對象是沒有 OpenAI Enterprise 合約的大學研究室 PI 或實驗室主管，已有 Enterprise 合約的學校則要透過原有企業存取流程申請。OpenAI 表示會驗證機構、PI 或實驗室主管身份、職務與管理權限，並審查研究活動、預定用途與指定的機構安全聯絡人。研究資料在此方案下預設不拿來訓練模型，但公告沒有把免費席位、使用限制與審核後的可用額度轉換成 API 或可重現的模型評測條件。

OpenAI 展示的用途包括藥物與蛋白質設計、疾病監測、疫苗與免疫反應、基因與 RNA 治療、農業、保育及抗微生物藥物抗性。頁面中的研究室案例與模型輸出由 OpenAI 提供；其中一個展示提示涉及 Nipah 與 Hendra 病毒相關的抗病毒設計，OpenAI 同時展示 GPT-Rosalind 的回答與另一模型拒絕提供序列級設計的回答，並註明這些評估只檢查文字是否完成要求，不驗證科學正確性或方法是否可行。

- 來源：[openai.com](https://openai.com/index/introducing-the-rosalind-academic-plan)

## Mistral 發布 5M 至 209M 參數的 Timestral 時間序列模型

Mistral 發布 Timestral 時間序列 foundation model，共有 5M、28M、123M 與 209M 四種規模，支援多變量機率預測、過去與已知未來的 covariates，context length 為 32,768 個時間步。模型採 Modified MIT 授權，程式碼已放到 GitHub，可在 CPU 上推理；Mistral 表示 209M 版本在 GIFT-Eval、TIME 與 fev-bench 三個公開 benchmark 的主要指標排名第一。

Mistral 公布的測試中，209M 模型在標準伺服器 CPU 的 8 執行緒上，使用三週的 15 分鐘資料預測一天，約需 140 毫秒；5M 模型約需 10 毫秒。28M 版本在部分測試勝過約四倍參數量的 Chronos-2，這些排名來自 Mistral 提交的單一 checkpoint 結果，技術報告尚待發布。

模型可透過 Mistral Forge 用私有資料微調，並部署到客戶硬體、VPC 或 air-gapped 環境。Mistral 也列出能源、製造、金融與維運等用途，但公告沒有提供各產業資料分布改變時的長期實測，也沒有把公開 benchmark 與企業資料的錯誤成本直接對應。

- 來源：[mistral.ai](https://mistral.ai/news/timestral/)
