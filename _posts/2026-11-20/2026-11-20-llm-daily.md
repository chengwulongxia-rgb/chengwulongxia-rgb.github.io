過去三天的新素材集中在 LLM 如何被放進可驗證的工作流程：Anthropic 報告 Claude Fable 5.2 參與黑洞理論計算，OpenAI 公開 Codex 在 ChatGPT 效能回歸中的任務編排，Google 則把工具 schema 的載入改成按需搜尋。另有一項開源瀏覽器展示，以少量權重編輯處理小模型的重複推理；這些結果分別來自公司研究報告、內部工程案例、API 預覽與單一模型實驗。

## 🔥 Claude Fable 5.2 參與兩個黑洞理論物理問題

Anthropic 11 月 17 日發布研究文章，表示 Claude Fable 5.2 參與兩個與黑洞及量子重力相關的理論問題。第一個問題是弱耦合的 N=4 super Yang–Mills theory 是否存在對應 Hawking–Page transition 的突變；Anthropic 說，Claude 以多個自身副本組成的 agent 小組完成一項 2003 年提出、此後未完成的計算，結果顯示該相變仍是突然發生，而不是平滑變化。

第二個問題是三維時空模型中的 modular bootstrap。Anthropic 表示，Claude 從數值結果中辨識出模式，借用其他數學與物理領域的方法，算出最簡單版本的精確上限，並證明該上限不能再降低。這個結果沒有找出正確的量子重力理論，而是縮小了可接受理論的搜尋範圍。

依文章描述，研究者先列出 22 個理論物理開放問題，再讓多個 agent 背景執行約六週。modular bootstrap 的結果由多個 agent 共同完成，其中一半證明沿用了 OpenAI 模型先前證明中使用的策略；Anthropic 表示，該結果在 9 月以 Lean 形式化驗證，主要結果也由物理學家檢查。

兩項結果都來自理論模型，不直接描述我們的宇宙，也沒有立即的實際應用。Anthropic 的文章與附帶論文記錄的是在特定模型、耦合條件與最簡化 bootstrap 版本下的結果，不能由此延伸為已完成量子重力理論或一般科學研究流程的自動化。

- 來源：[Anthropic](https://www.anthropic.com/research/claude-black-hole-physics)

## OpenAI 用 Codex 追蹤 ChatGPT 效能回歸

OpenAI 11 月 19 日介紹內部 Performance Factory。公司表示，這套雲端系統會在效能告警出現後建立任務，讓 Codex 依序調查回歸、記錄根因、提出修正，再於部署後確認效能是否回到基線。OpenAI 說，Regression Workflow 運作三個多月以來追蹤超過 1,700 件調查，找出超過 600 件根因，平均每天約 17 件自動調查。

系統由任務服務、派工迴圈、雲端 Codex 執行環境與事件訂閱組成。任務以設定檔和 Markdown prompt 定義狀態、轉換條件及需要工程師介入的步驟；Codex 使用服務身分存取程式碼儲存庫、metrics、logs、traces、CPU profiles 與 memory snapshots。GitHub 審查留言或部署完成等事件，可喚醒暫停中的任務。

OpenAI 表示，早期 agent 有時會停在第一個看似合理的解釋，因此加入另一個 Codex session 進行 adversarial review，要求重新檢查假設與反事實。在人工檢視的 100 個根因建議中，OpenAI 將 70% 評為準確，另外 30% 需要進一步修正或尚未充分建立因果關係。這項比例來自公司自己的案例檢視，不是跨組織的準確率。

修正程式碼仍須由工程師審查並決定是否合併。OpenAI 也寫明，agent 提出的修正有時過度複雜或引入新問題；涉及快取與資料新鮮度等架構取捨時，仍需要熟悉服務的工程師判斷。公司正在以歷史事故回放與合成效能測試評估 agent，並探索讓低風險修正不經人工介入發布，但這不是目前流程的既定權限。

- 來源：[OpenAI](https://openai.com/index/how-openai-performance-factory-keeps-chatgpt-fast)

## Gemini API 預覽 Tool Retrieval，按需載入工具 schema

Google 11 月 19 日在 Gemini Interactions API 預覽 Tool Retrieval。開發者可以把不常用的 function schema 標記為 `defer_loading: true`，並加入 `tool_search`；模型收到任務後先搜尋工具名稱，再只載入相關參數 schema。Google 的示例使用包含 50 個以上延後載入 function 的工具清單，模型找到 `issue_refund` 後才取得其參數並進行一般 function calling。

這項機制針對每次請求都傳送完整工具庫的情況。Google 表示，當 agent 連接數十到數百個工具時，完整 schema 會增加輸入 token、延遲，並使工具選擇變得較不準確。Tool Retrieval 不另收費，仍依所使用模型的標準輸入與輸出 token 計價；官方文件列出的支援範圍是 Gemini 3.6 及之後版本，包括 Gemini 4 系列，且目前是 Interactions API 的 preview。

Google 的伺服器端版本不需要開發者建立或託管索引，常用工具可以維持預先載入，較長的工具清單則延後載入。官方也提供 client-side retrieval：若開發者有自己的工具 registry、embedding index 或使用者權限篩選器，可以由自有的 `tool_search` function 回傳符合條件的 schema。這表示工具搜尋的權限與結果仍可由應用程式自行實作，但也需要自行處理其篩選規則。

Google 表示延後載入的 schema 會避開 prompt 開頭，並可與 prefix caching 搭配。公告提供的是 API 行為、支援模型與示例，未在該頁提供不同工具數量、任務類型或模型設定下的獨立 token 與準確率對照。

- 來源：[Google](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)

## Weight-Space Playground 展示以權重編輯降低重複推理

TabbyML 團隊發布 Weight-Space Playground，讓使用者在瀏覽器中比較原始與編輯後的 Qwen3.5-0.8B。專案頁描述的實驗不是 fine-tuning，而是直接修改 64 個 neuron 的 output weights，總計 131,072 個權重；編輯目標是模型在推理時反覆檢查相同內容、消耗 token budget 卻沒有完成答案的情況。

專案頁引用原始實驗的 MATH-500 測試：在相同 prompt 與設定下，原始模型有 93.0% 的執行到達 32k token 上限，權重編輯後為 33.1%；MATH-500 準確率則由 7.9% 變為 48.1%。頁面同時標示仍有部分執行到達上限，並說明這些數據來自原始實驗發布的評估，不是瀏覽器頁面重新跑出的完整測試。

展示頁可播放離線錄製的 token stream、查看兩個模型的權重差異與指定 neuron 的活動，也能在裝置端透過 llama.cpp、WebAssembly 與 WebGPU 執行比較。瀏覽器執行時需下載約 1.05 GB 模型；頁面指出，原始模型使用 Q4_K_M imatrix，編輯模型使用另一種 Q4_K_M 量化，兩者的量化校準差異也會影響比較。

頁面列出的神經活動觀察來自 4 個重複案例與 1 個 control，並明確標示為 observational evidence。這是針對 Qwen3.5-0.8B、特定量化與重複推理行為的實驗展示，尚未提供其他模型、任務或更大規模評估的結果。

- 來源：[Weight-Space Playground](https://tabbyml.github.io/weight-space-playground/)
