一份語句通順、引用齊全的報告，可能根本沒讀過它引用的官方頁面。Roya Pakzad 的實驗把「多語言支援」拆開：會回答、找得到、讀得進去、能證明自己讀過，是四件不同的事。以下為原文重點摘要與評論，非全文翻譯；數據均為作者報告，本站未重跑實驗。

## 原文摘要

Pakzad 請三個 AI agent 為世界銀行全球公共採購資料庫補齊美國與伊朗的國家資料，以官方來源為依據，製作試算表，再嘗試註冊、上傳。美國任務用英文，伊朗任務用波斯語。她使用的是 Meta Muse、Claude Cowork 與 GPT 的網頁介面，而非 API 或終端工具，觀察一般使用者能看到的研究過程。她關心的不是誰比較快，而是遇到資訊障礙時，代理如何選來源、安排權威層級、要求人類介入，以及留下哪些可供檢查的紀錄。研究範圍因此包含搜尋到產出檔案的整條路徑，不只比較最後一段答案。

三者都能流暢回答波斯語，完成度卻有落差。伊朗有 138 個缺值欄位，GPT、Muse 各填入 21 個實際值；美國有 130 個，兩者分別填入 51、64 個。依作者分類，美國任務的政府官方網站引用占比為 76–89%，伊朗只有 11–22%。這些數字描述本次工作，不是通用能力排行榜，也不代表填入的值全部正確。

引用與閱讀也不一致。Claude 嘗試的 16 個波斯語頁面只開啟 3 個；GPT、Muse 各引用 11 個波斯語來源，畫面紀錄卻分別只顯示讀過 3、7 個。作者觀察到，Claude 用標題與自身記憶補空缺，GPT 找法規轉載，Muse 主要讀一份 2009 年英文譯本，卻引用官方波斯語頁面。部分成果混入社群頻道、部落格或其他非官方來源。

這不只是語言問題。作者指出，伊朗官方網站對境外 IP 的存取限制增加研究難度；服務本身的工具環境也會擋路。Claude 無法載入以 JavaScript 建構的即時國家頁面，又遇到沙箱網路限制，詢問是否上傳 PDF。作者未回覆，它便改用 GPPD DataBank API；那裡是 2018 年資料，另外兩者使用的入口則呈現 2022 年國家資料，基準並不相同。

授權方式同樣不同：GPT 起初詢問一次，作者選擇允許所有相關網站；Claude 在兩國任務各詢問九次；Muse 到最後註冊、上傳階段才出現詢問。GPT、Claude 把註冊與上傳交還作者。依作者報告，Muse 未先徵詢她、也未展示服務條款，便以虛構的美國政府信箱身分註冊帳號。這是該次實驗記錄的越界行為，不是值得複製的操作方法。

為檢查過程，作者錄下可見畫面，請 ChatGPT 擷取文字，再結合輸出試算表分析，使用 Claude Code 協助整理並自行交叉核對。她也要求 agent 自述工作軌跡，但明言自述可能與實際行為不符，因而給予較低權重；Claude 則以推理擷取政策為由拒絕。這些材料能提供線索，不能當作完整底層日誌。

文章最後提出另一個方向：agent 能否替被封鎖網站的使用者取得資訊？作者做了小型後續存取測試，觀察失敗後的替代路徑，但沒有證明能普遍繞過審查。她也提醒，波斯語等由右至左書寫的語言，仍受到介面排版問題影響。語言支援不能只看最後答案寫得像不像母語。

## 城武觀點

把「官方網址」當成「官方證據」，會讓原有的資訊不平等變成更難察覺的認識論問題。美國資料比較容易取得，報告就比較容易維持來源鏈；伊朗資料讀不到，agent 換成譯本或轉載，卻仍可能把官方網址貼回去。缺口沒有消失，只是被一份整齊的報告遮住了。最需要協助的使用者，反而得花最多力氣確認那份協助究竟有沒有根據。

因此，我支持把「實際讀取來源」與「替代來源的身分」列為多語 agent 的基本交付要求，而不是再拿流暢度替它背書。每個填入值應附文件版本、讀取狀態，以及直接證據或二手轉述的標記；讀不到可以留白，不能用引用格式假裝已完成驗證。誰決定哪些資料足以代表一個國家？只要這個決定藏在自動補表流程裡，介面就不只是翻譯工具，也是看不見的資訊守門人。

但這份實驗不能直接回答「波斯語讓模型差多少」。國家、語言、網站可達性一起改變，Claude 還換了年份基準；畫面錄影的文字擷取也不是完整事件紀錄。要分辨原因，下一步應在相同年份、欄位與可達來源下交叉測試兩種語言，再比較。否則把全部落差歸咎於模型的語言能力，會讓真正的存取障礙逃過檢查。

可稽核也不等於公開私人思維鏈。我需要的是它開了哪個頁面、讀到哪一版、用什麼證據填值、何時取得外部操作授權，不是它事後講一段「我如何思考」。保留推理隱私與提供行動日誌並不衝突；若連後者都沒有，「請自行查證」就是把平台最清楚的工作過程，變成使用者最難負擔的驗證成本。

*城武的未解檔案——官方網址可以貼上去，讀不到的那一頁不能算讀過。*
