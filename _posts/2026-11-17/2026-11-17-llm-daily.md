過去三天的素材集中在 LLM 與既有系統的接合：Windows 11 的診斷元件被逆向工程研究發現會記錄部分 coding agent 與開發工具是否出現，Qwen 發布具備長上下文與工具執行能力的 Qwen4-Max，OpenAI 則公布讓外部評估者長期接觸內部模型與系統的第一階段安排。OpenAI 同期也推出只對美國部分 ChatGPT Pro 使用者開放的代理支付錢包。以下分開說明已取得的實測、公司自述與尚未公開的限制。

## 🔥 Windows 11 MissionControlAggregator 記錄 coding agent 使用位元

逆向工程研究者 Xusheng Li 檢查 Windows 11 的 `MissionControlAggregator.dll`，在元件中找到對 `codex.exe`、`claude.exe`、`copilot.exe`、`cursor.exe`、`antigravity.exe` 等檔名的比對，也找到 Node.js、Python、.NET、GCC、Clang、GDB、Java 編譯器與 VS Code 等開發工具名稱。研究者將相關功能識別為 `CLICodingAgentUsage62580080`，並指出它同時涵蓋命令列與桌面應用程式路徑。

研究者追蹤到的資料流包括 WSL 執行事件、KernelProcess 的應用程式狀態事件，以及 Win32k 的應用程式互動事件。符合比對後，元件會在 `Segments.SubCohorts` ETW 報告中設定分類位元；報告記錄的是一段收集期間內是否觀察到特定工具，不是每個工具的使用時長。原文也指出，來源事件包含執行時間、焦點時間、互動計數與資源使用量，但該元件似乎只保留工具是否出現的 bitmap。

作者在一台 Windows 11 ARM64 虛擬機中實際測試，執行複製的 `codex.exe` 後捕捉到 coding-agent 的分類位元，也在開啟 optional diagnostic data 的設定下，於 `DiagTrack` 的 `EventStore.db` 找到可供上傳的 `Microsoft.Windows.MissionControlAggregator.Segments.SubCohorts` 事件。該測試環境為美國地區設定；作者說明，公開 ISO 的基準虛擬機預設關閉相關功能，因此不能由此推論所有 Windows 安裝都已啟用。

依作者的測試，optional diagnostic data 在美國安裝流程中預設開啟；使用者可以在安裝時拒絕，或到 Windows 的 Diagnostics & feedback 設定關閉。這篇文章是單一研究者對特定 Windows 組建與虛擬機的逆向工程與測試，未提供 Microsoft 對該功能目的、資料保留期限或各地區預設值的正式說明。

- 來源：[Xusheng Li](https://xusheng.dev/posts/windows-coding-agent-telemetry/)

## Qwen4-Max：2.4 兆主幹參數、每 token 啟用 710 億參數

Qwen 11 月 16 日發布 Qwen4-Max。官方文章稱模型採用 Qwen4 系列新架構，主幹參數為 2.4 兆，每個 token 啟用 710 億參數，另有 3280 億 N-gram Embedding 參數，並支援原生視覺能力與百萬 token 上下文。文章列出的架構元件包括 GDN、Qwen Sparse Attention、Gated Residual 與 N-gram Embedding。

Qwen 以自家 Work360 行業基準比較 Qwen4-Max 與 Qwen3.8-Max，前者得分 52.69、後者 47.74。官方也報告，在 Work360 的兩種推理強度下，Qwen4-Max 的 token 消耗相較前代減少約 24% 至 58%；評測說明列出 JobBench、APEX-Agents、CodeArena、AgentArena 等外部排行榜或資料集來源，但文章中的多數結果仍是 Qwen 的發布資料，沒有在該頁提供獨立重現結果。

產品展示涵蓋 Blender、Unity、Unreal Engine、Godot、汽車製造、金融研究、法律盡調與醫療流程。Qwen 舉例稱，在一個加工編程案例中，人工投入由約 475 分鐘降至 24 分鐘；在雲端資源調度案例中，官方報告模型調度費用相對參考基線平均降低 10.42%，GPU 線上分配的整機空閒容量時長提升 4.62%，CPU 離線重調度達到最佳目標的求解速度提升超過 14.61 倍。這些數字是特定案例與基線下的結果，文章沒有把它們描述為跨場景的保證。

官方文章還描述一項 48 小時、4 輪「分子設計—合成測試—主動學習」流程，以及一項藥物候選分子探索：後者累計呼叫工具 454 次、完成 3,239 項計算指標評估，並稱候選分子的名義結合親和力約為起點的 3.6 倍。文中同時寫明該候選分子仍需進一步濕實驗驗證。Qwen4-Max 已可透過千問 AI 平台的 Token Plan 或 API 使用，也可在列出的 Qwen 產品中使用；文章未宣布該 Max 模型開源。

## OpenAI 與 Apollo、Goodfire、METR、Transluce 進行嵌入式評估

OpenAI 11 月 16 日表示，已與 Apollo Research、Goodfire、METR、Transluce 簽署第一階段嵌入式評估協議。依官方說明，評估者可依任務取得部分內部模型、模型 checkpoint、原始碼、訓練與評估資料、監控系統、技術文件，以及與負責研究的員工討論；初期範圍集中於訓練與內部使用期間的 alignment 和 safeguards。

Apollo 將評估模型是否可能暗中違反開發者意圖，以及現有安全措施能否偵測這類行為。Goodfire 將以其平台分析模型內部，主要處理訓練執行監控、除錯與 alignment。METR 的第一階段將檢查 OpenAI 最大的強化學習訓練之一，包含既有測試與監控可能漏掉的失敗；OpenAI 特別註明，這個範圍小於 METR 原先提出的廣泛 misalignment 調查構想。Transluce 則將檢查 post-training alignment 評估的品質與涵蓋範圍，雙方另有意在 2027 年初進行約八週、具更廣泛存取權的後續評估，但該後續安排仍屬意向。

需要存取敏感資料的評估者將在 OpenAI 辦公室、使用 OpenAI 提供的裝置工作。OpenAI 的 Safety and Security Committee 將可在評估前、中、後行使監督職責並收到未刪節報告；若 OpenAI 與評估者發生爭議，會先升級至 Safety Advisory Group 與 OpenAI 高層，仍未解決時交由該委員會處理。

OpenAI 表示評估者保有發表獨立評估的權利，但公司保留刪除機密資料的權利，也可以要求延後披露，以處理可能造成安全或保安風險的發現。Apollo 與 Goodfire 接受金錢報酬，官方註明報酬不以評估結果為條件；METR 與 Transluce 不接受金錢報酬，但可能接受 API 額度或評估所需算力。這些安排說明了存取、保密、爭議處理與發布條件，實際評估結果與公開報告仍待後續產出。

- 來源：[OpenAI](https://openai.com/index/our-first-phase-of-embedded-assessments/)

## ChatGPT Wallet 先在美國 ChatGPT Pro 的 dots 開放

OpenAI 11 月 13 日推出 ChatGPT Wallet，與 American Express、Chase、Mastercard、Visa 合作。官方描述的流程是：使用者先加入信用卡，每次購買前檢查商品、總額與選用卡片，再透過 Face ID 或指紋等安全檢查核准；付款網路之後提供替代實際卡號的 payment token，讓商家與 agent 不必取得使用者真正的卡片資料。

OpenAI 表示，使用者仍直接與商家交易，商家保留定價、履約、退貨與客服關係；符合資格的爭議處理則沿用卡片原有的回饋與保障。官方也表示，未來預計讓使用者設定支出上限、商品類別或時間範圍，預先授權 agent 完成購買，但這是後續規劃，不是本次初始流程的開放功能。

目前 ChatGPT Wallet 透過 dots 推出，初期對象是美國、年滿 18 歲、使用 ChatGPT Pro 且持有符合條件美國發行卡片的使用者。OpenAI 說會先從有限度使用開始，與商家、銀行及支付網路調整相容性與可靠度。商家若要支援這類交易，還需處理 agent 存取網站、Web Bot Auth、支付與風險系統誤判，以及現有結帳流程對 agent 的相容性；OpenAI 已另發布 Commerce Partner Playbook。

因此，本次公告是有限資格的代理支付推出，不是所有 ChatGPT 使用者都能使用的通用錢包。OpenAI 未在公告中提供交易量、拒付率或詐欺率等實際運作數據；預先授權購買也仍列在未來規劃中。

- 來源：[OpenAI](https://openai.com/index/introducing-chatgpt-wallet)
